## M0 可以立即验证的事项

- Electron 外壳与 video-canvas Renderer 的 React Flow/Three/媒体 API 兼容性，记录实际版本；不把未迁移业务标成完成。
- Provider JS 契约的 Goja sidecar/替代引擎样例：纯钩子、utils、异步状态、资源限制、跨平台打包；选择运行时后形成 ADR。
- 最小项目保存/恢复和双实例占用验证，检验底层文件系统假设；验证代码不直接等同于正式项目存储实现。
- FFmpeg 镜头顺序拼接、不同媒体参数、无音轨和可选 BGM，确认编码与许可；形成首个导出 profile。
- 工程工具链和测试执行入口。测试文件路径以实际模块结构统一后更新，不沿用与工程布局冲突的占位路径。

每项只需先写短验证任务卡：假设、样本、成功/失败标准、记录位置。M0 可以与数据契约和迁移台账并行推进。

## 可延后的详细设计

- 完整短剧、营销和 3D 导演台：现在明确迁移台账、依赖、版本去向和数据扩展点；接近对应批次时再写详细交互、接口与 AC。
- 官方模型、账号、积分：预留执行来源与服务边界，不让其阻塞本地自定义模型。官方阶段前单独冻结执行/凭证/结算与权限契约。
- 组织、共享空间和同步：目前预留稳定项目/资产 ID 与 schema 版本；同步冲突、权限和计费细节在对应阶段设计，不预建完整后台。
- 发布签名、公证、更新和安装包：M0 确认技术可行性及依赖许可；产品发布前补齐发布/回滚/诊断方案，不作为本地开发首批编码的统一前置条件。

## 推荐推进顺序

1. 统一版本范围，建立全量能力迁移台账，确定首批节点与工作区流程。
2. 工程基线和 M0 验证并行；将结果回写插件、媒体、存储选型。
3. 先冻结项目与资产及必要的桌面 API，使 V1-FR-001/002 达到 Ready 后开发。
4. 依次冻结画布、Provider/配置 Agent、任务、媒体输出的当批契约，再迁移实现和验证。
5. 每批完成后补实现证据并重做当批门禁；首阶段发布时统一验收本地创作闭环。
