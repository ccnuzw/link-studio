# 小灵与小镜同状态验收

基线为 `video-canvas@4277d16f40457664e27a89efabac14d07c1d73e8`，不是参考仓库的当前工作树。验证环境为 macOS、Node 22、Electron 源码构建；模型和媒体请求使用本机回环服务，不使用真实凭证或收费服务。本记录不代表整款应用已像素一致。

## 架构与判定口径

小镜的网页、Go 工具服务和 Agent 引擎是三个边界；小灵并非把整个服务原样嵌入 Electron。`packages/agent-runtime/src/runtime.ts` 复用迁入的 `AgentEngine` 和 SQLite 事件存储，再装配设置、画布、短剧三个工具入口。桌面主进程通过 `src/main/settings/agent.ts` 连接 Worker；`src/main/project/canvas-agent.ts` 校验会话读过的节点并落地项目操作，`src/main/project/generation.ts` 执行媒体任务。会话历史与项目画布不是同一个存储；重启后既要恢复历史，也要查证任务是否已经提交，不能只看消息有没有重新显示。

## 从用户入口验收

### 后台系统通知：批准生成、隐藏窗口、点击回窗

固定版的 `use-agent-notifications.ts` 只订阅当前画布的实时事件，而非会话历史。桌面复用同样的两个触发点：待批准的生成，以及生成结束后 Agent 自动开新一轮验收。收起小灵面板、窗口失焦或插进正在进行的对话，都不是独立通知理由。用户首次批准生成时可以允许或拒绝，选择保存在本机 SQLite；不支持原生通知时不询问。此授权是应用偏好，不会更改操作系统授权，也不会放开 Electron 的网页权限。

`tests/e2e/generation.spec.ts` 从真实桌宠进入画布审批，用回环供应商控制任务完成时机。拒绝生成不询问；只提交时拒绝系统通知，任务仍完成。允许后重启，没有历史补发；隐藏窗口后收到「生成闭环验收：生成已完成，Agent 正在验收」，点击回到结果分隔行。再次发送生成请求并隐藏窗口，收到「生成闭环验收：Agent 需要你批准一批生成」，点击回到待审批卡。另一用例在已授权且窗口隐藏时把结果插进用户正在进行的对话，SQLite 有 `steer=true`，通知数为零。实测隐藏的 Electron 窗口可能仍报告 `document.hidden=false`，因此同时判定窗口原生可见性，不以失焦替代后台。

验证到 **Electron 原生通知 API 边界**：测试替换 `Notification.show` 以记录实例，并触发其点击事件；未向用户的系统通知中心实际投递。macOS 勿扰、安装包签名、操作系统拒绝以及其他平台的原生弹层外观均未验收。标题和桌宠气泡不计入通知证据。

### 桌宠图集：加载回退与暗色描边

基线的内置黑猫在缩放后才绘制暗色浅描边；桌面原图集相同，但未绘制这层描边。`pnpm build && node scripts/compare-agent-pet.mjs` 分别构建固定提交组件和挂载桌面组件，使用各自图集、关键帧及生产样式，按每帧停留时长取中点并断言实际图集坐标。10 行共 63 帧，80px 桌面、56px 窄屏、60px 探头精灵，分别在浅色和暗色下比较。修正前暗色 80px/56px 两张拼图分别有 79,789/48,553 个不同像素；修正后 **6 张拼图、378 个帧状态连续两次零差异**。结果在 `test-results/agent-pet-parity/report.json`，不包含探头容器裁切、浮窗、气泡、淡入及动作切换时机。

`tests/e2e/canvas.spec.ts` 在新建项目之前延迟或拒绝内置图集的解码：初始不闪胶囊，约四秒未就绪才出现替代按钮，点击能打开小灵；图集迟到后自动换回桌宠。解码失败则直接退回按钮，在同一应用会话内关闭、重开项目不重复解码。另验主题切换、拖动不误开、隐藏和恢复、重启保留偏好及打开面板后的探头。三条桌宠 Electron 用例通过。

### 画布后台生成：登记、重启、取消跟进和只提交

从画布桌宠打开小灵，引用已有图片并请它生成另一版。小灵新建空节点、绑定模型、连入光线设定，不覆盖原图。批准前没有向媒体供应商提交新任务。批准后，`generate_media` 默认跟进：监听条显示「后台等待生成 · 0/1 已结束」，键盘展开可见生成状态，点任务名会选中对应节点。进度来自当前画布会话的持久化监听批次，不靠当前消息页推断。收起面板，窗口标题仍提示「⏸ 待批准 · 」或「⏳ 0/1 · 」；提问和审批优先，已排队交付不再显示进度。标题保留桌面品牌，关闭项目或进入设置不会遗留前一画布的进度。

`tests/e2e/generation.spec.ts` 使用真实 Electron、本地 SQLite 与回环异步媒体供应商，分别验证：

- **默认跟进**：批准、生成中退出、重开后恢复等待；供应商完成任务后，Agent 自动继续，结果可定位，供应商只收到一次提交。
- **不用等了**：关闭应用后向当前测试会话写入 55 轮夹具消息，让登记事件落在最近页之外。重开看到第 55 轮而未装载第 1 轮，监听条与窗口进度仍在。按 Enter 取消后条与前缀消失，数据库状态只有 `waiting → canceled`。生成照常完成，不额外调用供应商取消接口，也不出现自动验收消息。
- **只提交**：模型用 `wait:false` 请求生成。仍须批准，任务中心显示完成；没有 `watch.updated`、`tasks.settled` 或等待前缀。运行器另验跨项目读取、跨项目取消和设置会话取消均被拒绝；在自己的空画布会话重复取消返回零。

`pnpm build && node scripts/compare-agent-card.mjs --watch` 挂载固定提交的 `WatchStripView` 与本机 `AssistantWatchStrip`。两种主题 × 320/400 像素视口 × 收起、展开、部分失败、结束待交付、15 项滚到底部；长任务标题走真实省略布局。DPR 1、相同底色，**20 组监听条矩形位置、尺寸及逐像素比较均无差异**。截图和数值见 `test-results/agent-watch-parity/report.json`。这是组件静态矩形，不含整窗、外阴影、悬停、焦点环或动效中间帧。

### 节点绑定：从模型选择到供应商实际收件

固定版 `backend/internal/agent/canvasgraph/{apply,mode,generate}.go` 与 `backend/internal/service/agent/generate.go` 将「配置节点」和「申请生成」分开。小灵现在用 `canvas_apply_ops` 设置 `model`、`mode` 和可合并的 `params`。同批次中的无效编辑不落盘；不允许经 `params` 写入参考素材或 `op`。节点详情返回模型、参数及已知模型可选的生成方式；同时支持文生图/图生图的模型由参考图自动决定，不允许指定方式。`generate_media` 的每个条目只收 `nodeId`，主进程从当前画布、模型注册表和项目素材推导请求，保留审批时的快照。普通画布按钮的多结果生成不受这个单结果限制。

本机 Electron 的五条路径使用真实项目、回环模型和异步供应商：在批准分支实际核对供应商收到的提示词既有「生成另一版」，也有上游的「落日从左侧照入」。拒绝分支没有发出请求。生成集成用例另从真实 PNG 产物出发，连入剧本和原图；审批期间改动剧本，旧申请被拒，再审批时，`/images/edits` 的 multipart 正文含更新后的剧本、「图片1」及原 PNG 字节。重复批准只返回原任务，原图及新图都不可直接再申请。另一用例覆盖视频方式、参数合并与重开，自定义数量从 3 收拢为 1，核对任务和产物均仅一份。

边界：这不是所有供应商和节点种类的逐项验收。角色音色、必要参考及审批计价另列于下；真实账户可用余额仍需单独比对。系统通知的证据与操作系统边界见本节前的专项验证。

节点绑定阶段回归：`pnpm typecheck`、`pnpm build`、`pnpm test`（462 项）、`pnpm test:agent:upstream`（145 项）及 `pnpm exec vitest run --project integration tests/integration/generation.test.ts`（62 项）通过。生产构建上的 Electron 测试通过 8 条：上述 5 条画布生成路径，加上桌宠拖动及重启、设置审批及试跑、短剧粘贴剧本及改稿。重新运行 `--watch` 和 `--settled`，20 + 8 组既有组件矩形均为零像素差异；没有将任何整窗标为通过。

### 角色主图与音色：从退回申请到成片

固定版 `backend/internal/agent/canvasgraph/generate.go` 与 `backend/internal/service/agent/generate.go` 区分普通参考、角色主图和音色、可裁掉的角色补充图。小灵从当前连线和手动参考去重并计算实际编号。生成中的主图不能当旧图使用；视频使用角色音色时必须带入主图、音频并开启声音。`tests/unit/compose-canvas-prompt.test.ts` 用固定版的十组组合提示词样例分别核对编号、正文和角色归属，另验超限、缺失、声音禁用和旧任务已被取代。

- `tests/e2e/agent-character-reference.spec.ts`：在已设定主图和音色的项目，从桌宠进入小灵。图生视频漏带音色时，模型收到原因，没有审批或媒体请求。改为全能参考、开启声音，四个镜头只勾选「来信」。回环 Seedance 端点只收到一项任务，核对 PNG、Ogg、正文中「图片1」和「音频1」及声音开关。任务中心显示已完成；退出应用后从磁盘重开项目，来信节点只有一个视频版本，素材哈希等于回环返回的 MP4，另外三个镜头没有产物。不据此判定合成声音像不像本人。
- `tests/integration/generation.test.ts`：取得镜头申请后才启动角色配音，画布修订不变，新预检和旧审批都被拦住。取消配音后可提交。另一条路径先生成两张不同 PNG 并连入只容一张图的模型，超限没有创建任务；断开一张后，`/images/edits` 正文只含保留的 PNG，重放批准没有第二次提交。
- 四项审批默认只露出前三项，收起不撤销勾选。固定版 `approval.go` 的 `resolveGenerate` 区分部分批准和全选，真正成功创建任务后 `approvalExecResult` 才写 `executed`；已勾选项和随后登记的任务不能从申请总数反推。桌面没有根据未知价格伪造账户扣款。
- Electron 核对模型收到的 `task_id` 与项目助手 SQLite 中的回执相同，只指向「来信」。另在生成任务落盘后、审批执行结果尚未登记时中止 Worker：整体批准（省略 `items`）和二选一均能从已批准项恢复，多次重开没有再次出站；二选一只为第二个节点登记等待并交付一次结果。
- `pnpm build && node scripts/compare-agent-card.mjs --generation-decisions`：用固定提交的 `ApprovalRow` 和桌面实际结果行，同样的四项申请，独立装载已执行、部分批准、拒绝并附长理由、执行失败、失效五种记录。在 320/400 宽、浅暗主题、DPR 1 下，**20 组行矩形、位置和像素均一致**，包括长理由的省略号。报告 `test-results/agent-generation-decision-parity/report.json`。这些是无积分标记的结果行，不是待审批整卡、整窗或五种真实故障路径的证明。

### 生成计价、部分批准与运行预算

在模型设置中发布按秒报价的回环视频模型（默认 6 秒，普通 2 分/秒，全能参考且生成音轨 5 分/秒）。回到画布，请小灵为四个镜头申请生成：审批卡预估 **66**，取消「街口」「门铃」「信封」后只剩「来信」，标题与批准选项同步改为 **30**。展开卡外的桌面出站明细可以检查端点、提示词和参考素材。批准后，实际只有一项请求发往回环供应商；模型收到该任务号，结果行、SQLite 审批 `quote_credits` 和运行 `spent_credits` 都是 30。这里的积分是本地模型配置的估价，**不是供应商账单或真实账户扣款**。

主进程用预检后带默认值的输入计价。单测覆盖 Unicode 码点（含系统提示和输出上限）、图生图、真实视频引用、声音开关及自定义规格。没有报价不等于免费：无预算限制时允许继续，混合报价展示已知小计和未定价提示；有限预算下缺价不放行。画布发起、批准与继续运行的可选预算遵循固定版 API 的单次 0–100000 整数范围，不增加基线对话框没有的预算输入框。真实 Worker 回归：预算 29、申请 42，全部批准或单批 30 均被拦截，审批保持待定；单批 30 并追加 1 后只执行一次，复点不再次生效。钱包余额是另一条链路，桌面未接入，不能用运行预算模拟余额不足态。

像素对照命令 `node scripts/compare-agent-card.mjs --generation-approval` 和 `--generation-decisions`，报告分别在 `test-results/agent-generation-approval-parity/report.json`、`test-results/agent-generation-decision-parity/report.json`。待审批卡比折叠、展开全选、部分选择、全不选四态；结果行在原五态外新增「已批准 · ✦ 30」。均为固定基线组件，同数据、320/400 宽、浅暗、DPR 1；卡外出站明细、动效中间帧、钱包余额和整窗不在比较矩形内。

本轮实测：**16 组待审批卡连续两次全部零差异，24 组结果行全部零差异**。比较时固定桌面生产样式和字体，确认 Geist 已加载并等待选项高亮的弹簧动效结束，不设像素容差。类型检查、生产构建、469 项单元、81 项生成与 Agent 集成、145 项上游引擎回归通过。将已构建的桌面程序复制到独立目录后，6 条 Electron 生成路径同批全部通过，包括跨重启编辑与撤销，不依赖测试运行期间仍在变化的 `out/`。

### 生成审批说明与结果抵达对话

生成申请最多 8 项，`reason` 按基线 Go 实现最多保留 200 个 Unicode 码点。画布能看到「申请生成 N 个节点」和模型给用户的说明。默认勾选但**不自动提交**，取消全部勾选后不能批准。拒绝时既可以不说明理由，也可以进入「拒绝，并告诉 Agent 怎么改…」；Esc 退出编辑并把焦点还给选项。回环模型实际收到了用户的拒绝说明，对话历史显示同一说明，未调用媒体提交。只提交模式的工具反馈也明确告知模型不会自动验收，不再作出与队列行为相反的承诺。集成测试区别验证 8 项能进入节点读取校验、9 项被参数层拒绝、200 个非 BMP 字符不会被截成半个代理对。

`tests/e2e/generation.spec.ts` 在同一台机器用真实运行器和回环模型跑通默认跟进、取消跟进、插入进行中的对话、拒绝并说明和只提交共 5 条路径。空闲交付显示「生成全部结束 · Agent 自动继续」；用户在同一会话发起新问题、模型尚未回复时让媒体任务完成，显示「生成全部结束 · 插进这一轮」。SQLite 中只有一次 `tasks.settled`，其 `run_id` 就是用户新问题的运行。键盘展开分隔条可查看桌面任务详情并定位节点；默认不再把结果当作普通消息卡展开。桌面运行器原有的“用户停止后只登记结果”分支现在写入 `receipt_only:true`，不把它误报为新开一轮；三条中止/恢复集成测试验证了此标志与实际调用次数。此标志适用于新写入的回执，不追溯重写旧历史。

`pnpm build && node scripts/compare-agent-card.mjs --settled` 使用固定提交的 `buildTimeline` 从事件生成文案，再挂载真实 `SettledDivider`；桌面挂载同状态组件。自动继续／插进当前轮 × 320／400 宽 × 浅暗主题，**8 组分隔线、图标与文字的整体矩形尺寸、位置和像素均一致**。报告：`test-results/agent-settled-parity/report.json`。该结论不含任务详情展开态、焦点环、审批卡或整窗。

### 长会话：重开、往前翻和追更

设置、画布和短剧共用两条游标：首次取最近一页，向上翻时只取首条事件之前的记录，实时追更只取末条事件之后的增量。服务端沿用固定提交 `agent/src/api/service.ts` 的 100 条目标页长和最多 20 次回查，按发起新一轮的 `message.user` 切页，不把插话当成轮次起点。旧页不能覆盖当前运行、审批或流式正文。同一面板切回已读会话时复用已读事件并补尾；退出应用后重新从最近页装载，不会把内存缓存当作持久化数据。

`tests/e2e/assistant-history-page.spec.ts` 分别从设置抽屉、画布桌宠和已导入剧本的短剧助手发送一条消息，等真实运行器收到回环回复，再向各自的隔离 SQLite 会话写入 90 轮、270 条测试事件，重启 Electron。三个入口均模拟事件表暂不可读：首屏显示「对话加载失败」，恢复后点击重试，先看到编号 58–90 的记录。旧页读取失败时保留现有消息，第 91 轮仍能独立抵达；重试补页后第 58 轮的视口位置偏差不超过 1 CSS 像素，继续翻到第 1 轮，没有重复。切到新对话不串记录，切回旧会话可看到全部 92 条编号提问。独立的 Responses 用例验证滚离底部本身不出现按钮，真正收到新内容后可点击「回到底部」。SQLite 单测另覆盖跨两个窗口的单轮、插话、恰好 100 条与没有更早记录。这些编号轮次是测试数据，不是 92 次真实模型调用。

### 上下文用量：从模型响应到三个入口

基线 `context-ring.tsx` 显示的是**最近一次主对话调用的输入**除以**当前所选模型的窗口**，不是账单累计，也不包含输出。桌面原来只在设置和画布显示诊断事件的最近输入，短剧没有入口；本地模型也没有云端结算 ID，导致运行记录里的上下文可能一直为零。现在由运行器写入本轮 SQLite 用量并发布 `run.usage`，保留已花积分；摘要、命名和活动说明不另算一次对话。没有报告用量的成功调用以请求字符数估算；内联数据 URI 的 base64 内容不作为文字计数。此估算不是供应商实际分词，含内联媒体的缺用量请求不承诺与服务端估值逐字相同。

Electron 通过本机回环核对：设置里输入 24,576、输出 11、窗口 32,768 时显示 `25K / 33K`、75% 警示，历史接口确有对应 `run.usage`；切换到 65,536 的模型而不发送，分子不变、警示解除。下一轮只用 1,500 时读数下降，新对话归零；供应商没有回传用量时，试跑待审批前的非零读数重启后保持。另验原生 Responses 返回 4,096 输入、23 输出，显示 `4.1K / 33K`。画布真实打开空环，短剧重新启用模型后可用键盘打开及关闭同一弹层。

### 自动整理：进行中、整理结果与重开会话

接上用量环单项留下的缺口：引擎发出的 `context.compacting` 不落库，只在当前会话的当前运行显示。三个入口在消息流末尾显示「正在整理较早的对话…」、运行秒数与停止提示。`context.compacted` 则在发生的位置留下分隔行；成功时到达同一轮第一条后续 `run.usage` 才将省略号替换为读数，此后的用量不再改写旧行。失败行没有虚构的「整理后」数字。用户可用键盘聚焦分隔行查看解释，Esc 收起提示。

`tests/e2e/assistant-compaction.spec.ts` 不直接向界面注入事件：从设置抽屉、画布桌宠和已导入剧本的短剧助手分别发送消息，由真实运行器调用只读工具，触发摘要请求。回环供应商分别暂停摘要和下一次主请求，让用例观察「正在整理」→「93% → …」→「93% → 20%」。成功时主请求读到摘要；失败时主请求没有摘要，后续工具调用不会再触发同轮整理。六条路径均检查重启后原文仍在、摘要不冒充回复、分隔行不重复；新会话无旧分隔行、用量归零，重选原会话能看到原结果。

`pnpm build && node scripts/compare-agent-card.mjs --compaction`：直接挂载固定提交的 `StatusLine`、`CompactionDivider` 与桌面对应组件。同一背景和定位下比较画布、设置、短剧，浅暗两色、320/400 宽，进行中、等待后续用量、已得到用量、未知窗口、失败五态：**60 组组件矩形几何及像素零差异**。DPR 1，减少动态效果，固定初始经过时间，不含悬停弹层、流光移动、历史载入及整窗。见 `test-results/agent-compaction-parity/report.json`。

### 配置执行结果：实际写入值、对象跳转与回滚审批

### 开拍草稿的有效期与长稿切分

固定基线 `4277d16f` 的 `backend/internal/service/drama_preflight.go`、`drama.go` 及 `web/src/pages/drama/upload-card.tsx` 将预检、重估、建剧分开。桌面端现在在预检成功后将去噪原文、原始码点数、文件名、SHA-256 保存为按项目隔离的 SQLite 草稿。改范围时只传令牌；取消重开复用未修改的草稿，改稿重新预检。成功写入项目时记下消费凭据，再删除临时行。过期、跨项目、已消费使用同一用户提示「文件已过期，请重新上传」。

### 五百万字小说：从文件导入到项目重开

上一节只证明了解析器。本轮以同一固定版的 `upload-card.tsx`、`drama_preflight.go`、`drama_job_snapshot.go`、`drama_text.go` 为准，把原稿送进真实桌面流程，而不是绕过界面直接调用解析器。

- **导入与容量口径。** 选文件时检查扩展名，点「开始」后主进程提取并预检，界面只收摘要和令牌，不再收整篇原文。非法 UTF-8 在点击后报错，文件仍可更换；TXT／MD／DOCX 均从这条路径进入。粘贴栏不再硬截到 24,000；与固定版网页相同，粘贴计数用 JS 字符串长度，文件提取用 Unicode 码点。二者对非 BMP 字符的计数不相同。文件仍限 32 MiB、DOCX 正文 XML 限 64 MiB。
- **500 万码点实测。** 同一 DOCX 双章原稿（长章主要由非 BMP 字符组成），多一个码点时被拒，正好 5,000,000 时开拍窗显示「500 万字」。只选首章建剧。32K 模型的完整研读提示超预算，桌面按固定版规则暂停，未请求供应商；在项目设置切到 128K 模型并恢复，回环模型收到含后文章节的全书抽样，但**规划**请求只含首章，并实际生成一集。关闭项目后校验项目内原文 SHA-256，再从最近项目重开，生成的集仍在，剩余章节可重新报价。此用例在隔离的生产构建中通过（8.9 秒），并未把 500 万字全部跑完分集生产。
- **持久化与采样。** 超过 24,000 UTF-16 单元的去噪原文在项目 `assets` 内按 SHA-256 单独保存；项目快照只留原文引用与元数据，集正文仍按原方式保存。集成测试把完整项目复制到新路径、删除原目录，再打开并验证完整原文；篡改原文后读取校验失败，不会按空稿处理。另用大于 1 MiB 的粘贴稿验证体裁模型收到与固定版相同的首、中、尾样本；抽样先于插件传输入口，不放宽通用插件负载限制。
- **回归与未过项。** 4 条 Electron 路径、92 项单元／集成测试、Go runner 测试、生产构建通过；固定版 Go 的切分、字数、哈希和 6 组体裁提示词对照仍通过。整库类型检查在并行新增的 `tests/unit/steer-queue.test.ts` 报 TS6142／TS7006，未计作通过。最新剧本开拍 48 组差 1,796–84,677 像素、小说 24 组差 2,017–5,190，**0/72 整窗零差异**；这不是导入卡或工作室外壳的视觉验收。仍须单独验证超 200 集剧本（目前有本地上限）、整剧所有分集的生产、应用内导出／恢复以及导入页各状态的视觉差异。
