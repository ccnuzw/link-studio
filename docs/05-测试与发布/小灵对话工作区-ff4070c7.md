# 小灵对话工作区验收

小镜基线固定为 `video-canvas` 的 `ff4070c7b23581b1a79eacbfeddc56f836562377`。对比脚本从 Git 对象导出源码。画布和设置都使用 1280 × 800 的 Electron 45.4.1 窗口，设备像素比为 2。

## 消息发送与回复

| 用户路径 | 已核验行为 |
| --- | --- |
| 发送消息、等待、收到正文 | 回环模型控制首段和结束时间。桌面实际发送，基线回放同一组事件。首段到完整回复保留同一个正文元素。 |
| 阅读回复和展开计划 | Markdown 标题、列表、引用、代码、表格、进度环和步骤布局均有截图和元素位置记录。停止、重发插话、再开计划后，输入框中上一轮的插话数为零。 |
| 使用模型与 Skills | 对话模型弹层向上展开，与按钮右边缘对齐、间距 8px，点击选项后保留弹层，Esc 返回按钮。两个入口共用本机模型偏好，重启后仍可用。画布图片和视频标签使用相同滑块动画。Skills 对照覆盖空目录和已导入技能，真实桌面测试覆盖搜索、插入和焦点恢复。 |
| 在草稿中编辑引用 | 两个入口共用 Tiptap。画布的模型、技能与节点可在光标处插入，退格整块删除，撤销恢复。跨行草稿中的同名节点保留各自的 ID。 |
| 选中节点后发送 | 光标处显示虚线占位，聚焦后变为节点引用。删除或撤销后，取消选中并重选才再次出现占位。Electron 端到端测试读取模型请求。保留的引用在正文中带分组 ID，删除后正文只剩用户输入的文字。新消息的画布目录省略 `selected`，分组行给出成员数量，成员行带所属分组和分镜摘要。历史气泡保留发送时的引用名。 |
| 发送失效的引用 | 画布在发送消息和插话前校验节点、模型和技能。桌面测试分别发送引用已删除分组和失效技能的草稿，核对界面点名提示原因、草稿全文保留、对话历史条数保持原值。 |
| 设置助手提问 | 单项选择或模型选择直接回答，支持数字键、方向键和回车。多项选择支持附加输入和自定义回答，按选择顺序提交。在输入框发新消息会跳过当前问题，回答记录留在原位置。 |
| 回答传给模型 | 端到端测试读取回环模型实际接到的工具结果。逐项核对单题答案、多题的题文和答案、空选填项、模型名称与记录 ID，以及跳过后的说明。 |
| 画布等待审批时补图 | 端到端和 Worker 集成用例核对图片像素数据随同一条插话发给模型、重启可恢复、历史只保存附件引用。 |
| 查看提问与回答记录 | 两端均核对工具组和提问卡相对窗口的位置、选项的位置，以及等待提示在卡片之后。回答后核对记录及题文、答案的位置。模型答案保留提问当时的显示名与 key。目录没有对应模型时，工具把原因交回模型。 |
| 运行失败后查看历史 | 回环供应商返回错误，从画布和设置各自发送消息，经 Worker 进入失败状态。改名、新建会话、从历史重新打开后，提示仍显示原来的错误。 |
| 步数用尽后继续 | 回环模型反复调用计划工具，到达步数上限，从状态卡点击「继续」，原运行收到最终回复，旧按钮消失。 |

回答记录的四张截图（画布、设置各两种主题）已加入零像素差断言。`question-and-resume.png` 将等待回答、完成记录和继续按钮按小镜在左、小灵在右排列。

## 复现

在 `link-studio` 根目录运行。默认参考仓库是同级 `video-canvas`，两侧均需已安装依赖。

```sh
pnpm agent:build
pnpm exec electron-vite build
node scripts/compare-assistant-workspaces.mjs
node scripts/compare-assistant-engine.mjs
node scripts/compare-assistant-catalog.mjs
pnpm exec vitest run --project integration tests/integration/agent-runtime.test.ts tests/integration/skills-agent.test.ts
pnpm exec playwright test tests/e2e/generation.spec.ts tests/e2e/settings.spec.ts -g 'S4 设置与画布|拒绝生成|设置助手审批、试跑与重启恢复' --output=test-results/assistant-journeys
```

打开 `test-results/assistant-workspaces/index.html` 并排查看 66 组样本。`picker-comparison.png` 集中展示模型悬停、设置弹层、视频标签和已导入的技能。`replay.json` 记录桌面事件，`geometry.json` 记录元素布局，`pixels.json` 中的 `differing` 统计任一 RGBA 通道有差异的像素，`oneLevel` 统计最大通道差恰为 1 的像素。尺寸不同时记录两张图各自的宽高。

`engine.json` 记录引擎的独立对照。脚本从固定提交导出原版引擎，与本地内嵌引擎分别运行相同的平台与模型夹具。十六组用例覆盖画布及后台回复、失败、提问与插话，以及画布工具调用、追加预算、批准和拒绝生成。等待回答时，两端都将插话保留到回答之后交给模型，点击停止则先记录插话丢弃，再结束运行。脚本逐个比较模型收到的完整 JSON，再比较持久化事件类型顺序、状态、最终消息及用量。

两个引擎还分别通过八项进程恢复测试，包括子进程被终止后按同一幂等键重放工具、超过恢复窗口后手动继续、审批跨重启、插话只读一次及连续重启上限。桌面平台实际接入的工具声明和提示词另走 Electron 路径。

`catalog.json` 记录直接运行固定版 Go 画布目录和首条消息拼装函数的结果。空画布、分镜表、含 211 个节点及重复选区的画布，分别生成 241、471 和 71400 字节。三组输入都逐字节相同，覆盖 Unicode 截断、JSON 转义、分组成员和省略节点数。

## 验收边界

44 组会话样本覆盖两个工作区、两种主题，以及空窗、等待、输出中、普通完成、Markdown、停止、展开计划、等待单选回答、回答记录、运行失败、步数用尽十一种状态。另有 16 组弹层、2 组技能草稿和 4 组节点草稿。明暗两种主题下，选中节点的虚线占位、聚焦后的节点引用、插入技能后的草稿各有整幅输入区的零像素差断言。布局断言按 CSS 像素取整，画布插入弹层位置允许 1/64 CSS 像素差。截图保留品牌文字与宿主背景。

这些样本仍有严格像素差，涉及回复正文、停止状态卡等区域。实际供应商请求、完整工具目录与真实超时路径仍需单独核验。固定版 UI 在 timeout 状态显示「继续」，其引擎只允许 interrupted、step_limit、budget_exhausted 续跑。预算用尽后直接继续会提示追加预算，画布追加成功后可以续跑。后台维持本机的预算权限边界。

核对本机运行环境时，参考仓库 HEAD 为 `ff4070c7`，运行中的 Web、Agent 和后端容器镜像均标记为 `8d3b09d1`。两版后端在画布生成逻辑上有改动。视觉和引擎对照脚本从指定 Git 提交导出。真实供应商双端验收还需要单独运行该提交的后端，使用同一模型配置记录请求与回复。

固定版后台的 `admin_query` 可查询全站用户和用量，`admin_get_resource` 可读取注册、SMTP 等系统配置。桌面端使用本机任务、运行和审计记录。画布与设置的输入框占位文字沿用桌面端的可读颜色。试用基线的 70% 不透明度时，设置输入框的浅色对比度为 2.88，低于现有回归测试要求的 4.5。
