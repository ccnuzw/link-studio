# 项目与技术现状

## 产品定位

产品中文名为“灵可”，英文名为 Link Studio，内置 Agent 为“小灵”。仓库/工程目录使用 `link-studio`；命名依据见 [D012](../06-决策记录/冻结决策.md#d012-产品与内置-agent-命名)。

Link Studio 是以视频创作为主线的本地优先桌面创作工具，面向个人创作者，并为后续多人工作室协作、官方模型商业化和组织管理预留能力。它不是以代码仓库为中心的编程工作台。

## 上游基线

本次设计基于审查时可访问的上游版本：

| 项目 | 基线 | 已有能力 | Link Studio 中的定位 |
| --- | --- | --- | --- |
| `LAIJiangFeng/fynvra` | `d1ef382` | Electron 桌面工程、Main/Preload/Renderer 分层、Typed IPC、Agent Host、密钥边界、应用生命周期与打包 | 选择性吸收桌面工程规范，不作为视频业务底座 |
| `zaylora/video-canvas` | `f0b8ced` | React 创作界面、画布、资产、生成任务、Provider、短剧、营销、导演台、Go 服务、账号与积分 | 视频创作业务底座，逐步桌面化并调整本地优先体验 |

上游版本会继续变化。正式实施前应记录实际 fork/commit，并逐项审查差异，不能假设此处基线等于开发时基线。

## 已确认的产品边界

- 桌面端是主要创作入口，项目默认保存在本地。
- 用户可以使用官方模型，也可以配置自己的模型。
- 官方模型目录、供应商、模型权限和积分规则规划由 Link Studio 官方后台控制；官方模型接入阶段需另行确定登录和执行路径。
- 用户自定义模型由桌面端直接请求，凭证保存在本机，不走官方推理和积分通道。
- 本地项目和自定义模型允许未登录使用。
- 未来可由用户主动把本地项目创建到共享空间，以便跨设备继续创作。
- 当前不做工作室自托管，不增加“工作室模型”作为独立模型来源。
- 目标为原项目主线与主要功能尽可能完整迁移；设置/画布内置 Agent 的工作机制是主线，不能简化为聊天框或插件作者。V1 交付共享引擎与核心双助手，专业域工具随对应域迁入，例外须登记原因与替代。
- 未来官方管理后台可以增加组织/工作室、成员、角色、额度和官方模型策略。

## 设计假设

- 首阶段先交付本地自定义模型；官方模型请求执行路径与消费结算仍待设计，不下发长期官方 Provider 密钥到桌面端。
- 本地自定义 Provider 通过桌面端 Main/Utility Process 调用，Renderer 不直接持有凭证或任意网络权限。
- V1 首阶段先交付桌面端本地项目和自定义模型闭环；官方模型安排后续阶段。
- 共享空间不纳入当前 V1，预留可迁移项目格式和稳定资产引用。
- 官方模型任务传输所需提示词、参考素材或生成输入前，应明确告知用户数据会发送到官方服务及相应供应商。

官方模型执行/结算以及请求中包含的创作数据如何告知和授权，仍需在官方模型阶段规格化，见 [产品与架构蓝图](../02-产品与版本/Link-Studio-产品与架构蓝图.md)。
