# 本地项目与资产契约

版本：项目格式 1；适用 S1 的 V1-FR-001/002，并约束后续画布、任务和导出。本文是本轮工程基线，产品行为见功能规格；跨平台锁和落盘可靠性必须由 M0 验证，不能只依赖本设计。

## 1. 标识、所有者和限制

- `projectId/assetId/nodeId/jobId/exportId/operationId` 使用独立 UUID；ID 不作为磁盘路径拼接输入。时间为 UTC ISO 8601；revision 为安全整数，从 1 递增。
- Main 的 ProjectCoordinator 是项目提交唯一入口；ProjectStore 管理快照，AssetStore 管理资产记录/Blob，CanvasService 管理画布；JobRuntime/MediaService 通过同一协调器提交，不直接写文件。
- 运行时 `projectHandle` 绑定窗口、目录和 owner，会话结束失效；owner token 不向 Renderer 暴露。跨设备项目副本不能沿用运行时句柄。
- 项目名 trim 后 1～100 个 Unicode 码点，拒绝控制字符与路径分隔符；名称只是显示名。目录创建使用安全派生目录名并以独占创建防覆盖，不能把显示名当任意路径。
- 首批工程默认：单个项目 JSON 快照最大 32 MiB；单次 IPC 控制消息 8 MiB；导入任务并发 2；流式读写，媒体不经 IPC 传字节。限制属于可调整工程配置，超限返回稳定错误而非截断数据。

## 2. 目录与权威快照

```text
<safe-name>.linkstudio/
  manifest.json                  可重建的发现信息，不作为多文件事务提交点
  state/000000000001-<hash>.json  不可变 ProjectState 快照；同一 revision 仅一个合法后继
  assets/sha256/<prefix>/<hash>   项目内原始/生成媒体 Blob，不依赖原扩展名
  runtime/jobs/                  非秘密恢复摘要；敏感任务句柄在设备 userData
  runtime/exports/               媒体任务配方、临时状态
  exports/                       用户选择保存在项目内的成片
  cache/                         可重建缩略图/代理媒体
  tmp/                           本次会话未提交文件
  .runtime/                      锁诊断信息；不随共享同步
```

S1 不建立并列的画布/资产 JSON 权威源，统一记录在 ProjectState，避免跨文件更新出现“资产已登记但画布未提交”。大型媒体独立 Blob；任务运行明细未来可独立 journal，敏感 handle/state 存设备 userData 的受控运行存储，项目只存引用和非秘密投影。资产登记/节点结果绑定/完成投影仍在一次 ProjectState 提交内完成。

### ProjectState v1

| 字段 | 类型与约束 | 所有者 |
| --- | --- | --- |
| schemaVersion | literal 1；未来更高版本不得写入 | ProjectStore |
| projectId/name/createdAt/updatedAt | UUID、名称、UTC 时间；projectId 创建后不变 | ProjectStore |
| revision/parentHash/commitHash | 正整数；revision=1 无 parent；commitHash 校验完整内容 | ProjectStore |
| assets | assetId → AssetRecord，无重复主键 | AssetStore |
| canvas | schemaVersion、revision、nodes、edges、viewport；新项目为空 | CanvasService |
| compositions | compositionId → 有序 assetIds、可选 bgmAssetId、audioMix | MediaService，自 S5 使用 |
| jobs | jobId → 非秘密状态/输出投影；S1 为空 | JobRuntime，自 S4 使用 |
| operationReceipts | operationId、requestHash、revision、结果摘要 | Coordinator；用于请求去重 |
| extensions | namespace → JSON；有类型时按域 schema 校验，无类型时保留 | 对应扩展域 |

快照校验采用明确的规范 JSON 编码（递归对象 key 排序，数组保序，UTF-8，拒绝非有限数和非 JSON 值），对去掉 commitHash 的内容计算 SHA-256。文件名由服务生成，不从内容接受路径。应用读取时不信任 manifest 的 revision，验证快照链后重建发现信息。

### AssetRecord v1

| 字段 | 类型与约束 |
| --- | --- |
| assetId/createdAt | UUID / UTC 时间 |
| origin | imported / generated / derived / exported |
| displayName | 只用于显示，不作为真实文件路径 |
| mediaType/mimeType | image / video / audio；经过签名/容器探测 |
| sha256/sizeBytes | 64 字符小写 hex / 非负安全整数；导入完整文件后确定 |
| importMode | copy / reference；省略输入时 copy，持久记录必须显式 |
| storage | copy 为 `{ kind: blob, hash }`；reference 为 `{ kind: external, locatorId }` |
| metadata | width/height/durationMs 等按媒体类型可选，数值有限且非负 |
| availability | ready / missing；删除记录为 tombstone，记录 deletedAt |
| provenance | 可选 jobId/sourceAssetIds；不含凭证、鉴权头或秘密 URL |

外部 locator 的绝对路径/平台 bookmark 保存在设备 userData 的引用映射中，以项目目录身份+assetId 定位；项目只存 locatorId 和内容 hash。项目移动到另一设备后重新授权，不能承诺外部引用随项目自动可用。

## 3. 提交与恢复协议

1. 获得有效会话所有权后，所有变更进入项目短写队列；检查 owner、expectedRevision 和 operationId。相同 operationId/请求 hash 返回首次结果；ID 相同但请求不同返回 OPERATION_ID_REUSED。
2. 若增加媒体，先在同一项目文件系统写临时 Blob、流式 hash、探测完整内容，fsync 后移入内容寻址路径。既有 hash 必须校验大小/hash 后复用，不能覆盖未核验文件。
3. 基于最新状态构造单一新快照，校验所有 ID/资产引用、revision 与不变量；写同卷临时快照并 fsync。
4. 以不覆盖已有终态文件的原子发布方式生成最终快照路径，再同步父目录（目标 OS 语义由 M0 验证）。这一步是提交点；失败不报告成功。manifest 更新是提交后可重建操作，其失败不能把已提交事务误报为未提交。
5. 返回已提交 revision；事件只在提交成功后发出。响应丢失时客户端用相同 operationId 查询/重放，不新建 ID 重复导入。
6. 启动时在唯一 owner 下校验版本、hash 与父链。末尾损坏快照不激活；恢复最后有效版本并显示恢复提示。链分叉/重复 revision 视为异常，不按文件名大小静默选赢家。

崩溃情形：Blob 已完成但快照未发布时只产生未引用 Blob；快照已发布而响应/manifest 未更新时恢复已提交结果。缺失 Blob 标记 missing，不把项目整体伪装损坏或自动删除资产引用。索引来自快照，可重建，不能由 cache 决定有效项目状态。

operationReceipts 在 S1 保留全部最小结果，不因普通日志轮转遗失；接近快照限制时明确提示，不能悄悄取消幂等。后续压缩/数据库改造另写迁移方案，不在原地切换数据权威源。

## 4. 单写所有权

规范化 realpath、目录文件身份及平台大小写规则得到资源身份；同实例重复打开激活原窗口。跨进程用经 M0 验证的原子系统锁/等效排他原语占用目录；诊断文件不能作为唯一锁。

锁从恢复前取得到关闭 flush 后释放。不得仅按心跳超时删除活动实例锁；旧进程已退出后才允许恢复。旧 owner 的异步返回不能写入新会话。不同项目目录可并行打开，不能仅按复制后相同的 projectId 互斥。外部移动/删除/替换目录时停止写入并提示重新授权。

默认仅对本机文件系统承诺排他和恢复语义；检测到不支持的网络/同步挂载时阻止可写打开并说明原因。具体检测与限制在 M0 平台记录中说明。

## 5. 导入、去重、外部引用与删除

- S1 默认接收 PNG/JPEG/WebP、MP4/MOV/WebM、MP3/WAV/M4A/OGG；扩展名仅筛选，实际内容由探测决定。SVG/HTML/脚本不能作为可执行内容加载；文本脚本在 S2 单独作为节点文本导入。
- 工程默认每文件 20 GiB，静态图片最高 100 MP；媒体探测最大 30 秒。容器可读不等于预览/编码均可用：不支持的编码明确提示，不能生成假缩略图冒充成功。资源上限需以媒体 spike 校准。
- 导入开始不登记 ready；取消/失败清理本任务临时文件，不改源文件。重复内容返回候选，让用户选择 reuse 或 independent。独立记录可复用同一 Blob，但 assetId 不同。
- reference 导入也计算内容 hash；每次访问先检查定位符可用性，文件属性变化时重新核验 hash。内容变化返回 ASSET_REFERENCE_CHANGED，不悄悄换成新媒体。重新定位必须匹配原 hash；换内容应作为新资产导入。
- 删除采用 tombstone：画布、任务输入/输出、导出配方/运行任务任一引用存在时返回 ASSET_IN_USE；须通过对应域显式解除引用后再移除。永不删除外部原文件。
- S1 不自动回收原始/生成 Blob 或历史快照；cache/tmp 在 owner 确认且无运行任务使用时可清理。后续垃圾回收必须同时考虑保留快照与运行时引用，不只看当前画布。
- 最近项目只删除入口，不删除项目目录。首批没有“应用内永久删除项目”接口，避免新增未定义的破坏性行为。

## 6. 升级与兼容

schemaVersion 大于应用支持值时阻止可写打开，展示可理解提示，不强行解析。需要只读预览时必须有明确兼容解析器；不能承诺任意新版本都能预览。

旧版本迁移是显式导入/升级过程：保留完整旧目录或快照，校验迁移结果后发布新版本。未知节点和 extensions 原样保留，不因本版没有 UI 就清除。Web 版导出包不等于本地格式，V2 显式导入器负责映射。

### M0-03 实现约束

- `src/main/project/` 是 Main 内部 spike，采用 fs-native-extensions 1.5.4 系统排他锁；固定 `.runtime/owner.lock` 文件不删除，锁的有效性来自内核和打开的 fd，不来自文件是否存在、PID 或超时。原进程退出由内核释放锁。
- 当前只允许 macOS 的 APFS（statfs type 26），其他文件系统/平台返回 `PROJECT_FILESYSTEM_UNSUPPORTED`；阻止 `Library/CloudStorage` 和 `Library/Mobile Documents` 路径。第三方任意同步目录无法全面识别，仍不在支持承诺内。
- 临时快照 fsync 后用同卷 hard link 独占发布，再 fsync state 目录；不覆盖旧快照。发布后任何异常都可能已提交，当前会话停止后续提交，重开后按原 operationId 查询/重放。manifest 更新失败只记录 warning，不否认已提交快照。
- 坏尾仅在前缀链完整且尾部修订连续时隔离到 `.runtime/recovery-*` 并提示；原文件保留。分叉、链中间损坏、缺修订、未来 schema 均拒绝自动可写恢复。
- 当前只以重命名演示领域提交，assets/jobs 等预留 JSON 尚非各域完整 schema；创建接口仍为内部路径 API，创建操作去重、directoryToken/projectHandle 和窗口协调器必须在 S1 接入时完成。
