# 实施基线与开发批次

日期：2026-11-19。本文是本轮面向实现的工程方案；已确认产品边界见 [冻结决策](../06-决策记录/冻结决策.md)。没有运行证据的选型明确列为验证项，不将其写成已经验证的事实。

## 1. 实施范围

V1 发布基线为：本地项目 → 素材导入 → 核心画布 → 自定义 Provider 插件 → 设置/画布双入口 Agent 辅助 → 生成结果入库 → 顺序拼接 MP4 与可选 BGM。D011 明确共享引擎和核心画布助手是主线，不能只交配置助手；官方服务仍为独立后续批次。

完整短剧、营销、导演台、角色卡和分镜专属工作流统一归入 V2；V1 为这些数据保留扩展和未知节点兼容，不把占位入口作为迁移完成。共享空间与组织归入 V3。最终整体能力覆盖以 [迁移台账](上游能力迁移台账.md)逐项验收，不以版本标题或文件复制数量衡量。

## 2. 工程结构

保留现有 docs，后续建立单一 pnpm workspace，不把两仓库的根目录和 lockfile直接合并。

```text
src/main/                     Electron 生命周期、窗口、IPC、项目写入协调器
src/main/services/linkStudio/ 项目/资产/凭证/插件注册/任务/导出服务
src/preload/                  显式 DesktopAPI 域与可释放事件订阅
src/renderer/                 创作工作区及迁入的 video-canvas UI
packages/link-studio-core/    无 Electron 依赖的 schema、领域规则、序列化与状态机
packages/provider-runtime/    Host 契约、纯钩子桥接；引擎在 M0 验证
packages/agent-runtime/       共享 Pi Durable engine/store、设置/画布工具及恢复
resources/provider-plugins/   迁移的上游内置插件与来源清单
resources/media/              分平台二进制清单及许可，不将真实密钥放入资源
tests/integration/            文件系统、子进程、插件、网络与媒体验证
tests/e2e/                    Electron 用户路径验收
tests/fixtures/               合成媒体、mock Provider、项目与损坏样例
scripts/                      边界检查、许可/来源检查和构建辅助
```

Renderer 只依赖 core 的安全 DTO 和 preload 类型，不导入 main、Node 内建模块或通用 HTTP/文件能力。Main handler 接收 unknown 后经 schema 收窄；core 不依赖 Electron。Provider/媒体/Agent 工作进程不直接改项目 JSON，结果提交给 Main 的项目协调器。

## 3. 工具链与平台

| 项目 | 实施基线 | 验证与锁定方式 |
| --- | --- | --- |
| Node / 包管理 | Node 22 LTS、pnpm 10；遵循上游最低 Node 22.19.0 | M0 确定实际 patch 与 packageManager，生成单一 lockfile |
| Shell/构建 | Electron 45、electron-vite 6、Vite 8 为上游候选组合 | 版本来自 Fynvra 基线，安装、Chromium 与打包实测后精确锁定；不声明已经兼容 |
| UI | React 19、Tailwind 4、Zustand 5、React Flow 12 | 保留视频业务组件，统一双方依赖差异；Three/Fabric/MediaBunny 按迁移批次引入 |
| 语言/契约 | TypeScript strict；独立运行时 schema 校验 | 优先验证 TypeBox/同类 schema 方案与 TS 工具链；IPC 校验不能仅靠编译期类型 |
| 质量 | Biome、Vitest、Electron E2E 测试适配 | 替换上游 Bun/oxlint 命令时保留有价值测试；不得静默丢测试 |
| 数据 | 项目 JSON/Blob；Agent SQLite 存会话/运行/审批/watch | 原 node:sqlite 与 Pi Durable 随共享引擎迁移，M0 验证 worker 支持，不取代项目权威源 |
| 插件 | API v1 兼容，优先验证最小 Goja runner | 不引入 Go 业务 HTTP 后端；替代引擎与资源隔离均需样例证明 |
| 媒体 | 本地 FFmpeg / ffprobe | M0 验证 H.264/AAC MP4 profile，记录构建选项和许可 |

工程默认先在当前 macOS Apple Silicon 环境验证，随后覆盖 Windows x64 与 macOS Intel；这是验证顺序建议，不代表首发仅支持某一平台。未在目标平台通过的能力须如实记录，不能因架构无平台分支就声称支持。Linux 暂不作为承诺平台。

### 计划建立的命令

`pnpm dev`、`pnpm build`、`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm test:integration`、`pnpm test:e2e`、`pnpm package:mac`、`pnpm package:win`。

当前没有 package.json，这些是脚手架必须提供的命令契约，尚不能执行；测试设计写出的路径也是计划资产，不是测试存在或通过的证据。M0 建立命令后再以实际输出记录结果。

## 4. 开发批次与进入条件

| 批次 | 内容 | 进入条件 | 完成条件 |
| --- | --- | --- | --- |

| S1 | V1-FR-001/002：项目与资产 | M0 基础工具链可执行；[本地数据契约](本地项目与资产契约.md)及相关 API 接入首批规格 | 重启恢复、默认复制、引用缺失、重复打开、写入失败与占用竞争验收通过 |
| S2 | V1-FR-003：核心画布 | S1 服务可用；映射与操作 schema 固定 | script/image/video/audio、分组、连线、保存恢复及未知节点兼容通过 |
| S3 | V1-FR-004/007/008：插件、共享引擎、设置助手 | 插件/Agent M0 通过，人工文本模型先可用，工具/回执 schema 完整 | 当前页上下文、完整变更单、密钥/试跑、插话/恢复，非仅草稿 |
| S4 | V1-FR-005/009：生成与核心画布助手 | S2/S3 稳定；本批插件、模型流/tool calling/媒体能力明确 | 人工与 Agent 编辑/布局/生成、审批/watch、unknown/恢复、撤销冲突通过 |
| S5 | V1-FR-006：基础成片 | 媒体 M0 通过、S1 资产可用、S4 主链路可演示 | 有序拼接、可选 BGM、输入快照、取消和覆盖保护通过 |
| S6 | V1 本地版验收与分发 | S1～S5 通过 | E2E、打包、诊断、许可、恢复与目标平台检查通过 |
| S7 | 官方服务独立增量 | 本地版不依赖本批；官方执行/凭证/资金 ADR 与规格先就绪 | 官方登录、模型目录、任务与消费闭环独立验收 |

S5 媒体引擎、S3 共享 Agent 与插件兼容可并行。V1 设置/核心画布助手共用引擎、scope 隔离；V2 扩展专业域工具，不再整体后置画布助手。发布必须通过 V1-E2E-02；例外必须登记。

## 5. M0 任务卡

| ID | 假设/样本 | 成功标准 | 失败后的处理 | 输出证据 |
| --- | --- | --- | --- | --- |
| M0-01 | Electron 外壳加载 React Flow，桥接最小 typed IPC；界面不依赖登录 API | 启动/构建/类型/最小测试可运行，preload 无通用 Node 暴露 | 调整真实版本组合后锁定，记录兼容差异 | 依赖锁、命令输出、边界测试 |
| M0-02 | openai 文本、openai-image 和至少一个 async 视频插件的本地 mock 响应，含参考媒体传输 | hooks/utils/request/state 兼容；直传/供应商上传可用或明确阻止缺失公网 URL；死循环可终止、权限和输出限制可证明 | 缩小已声明支持集合或换引擎，不能绕过隔离或静默上传官方存储 | 插件 hash、样例、runner 记录；真实调用另行记录 |
| M0-03 | 两个进程竞争真实项目目录，保存时故障注入 | 单一 owner、无半快照激活；原 owner 退出后恢复，活动 owner 不被超时抢占 | 替换锁原语/提交协议；不开放多写 | 故障点矩阵与跨进程测试 |
| M0-04 | 两段可区分镜头、参数不同和无音轨样例，长/短 BGM | MP4 顺序与时长正确，音画同步，UI 不阻塞；构建可分发 | 调整滤镜/编码参数和二进制方案 | ffprobe、帧/音轨断言、许可清单 |
| M0-05 | 原 Pi Durable engine/store、SQLite/QuickJS、流模型/tool calling、双 scope | 无云依赖；审批/插话/watch/崩溃恢复有 fixture，目标回执防重复，秘密留宿主 | 修复 bridge/环境，不以简化聊天循环替代；保留人工配置 | SDK/worker、原测试映射、scope/回执/恢复证据 |

未完成项不得标记通过。M0-01 完成后即可实现 S1 的纯 schema/项目服务和测试；跨进程锁仍须 M0-03 通过后才能开放可写项目窗口。

## 6. 设计与后续规划的停止线

本轮后可以开始 M0 和 S1 的实现准备，不以 V2/V3 全部详细规格为前置条件。开发中只在当前批次存在影响正确性的接口/数据缺口时补当批设计，不重复启动一轮全产品规划。

V2/V3 目前维护目标、能力清单、依赖、非目标和进入条件即可；对应域进入开发前，再写独立规格和 AC。新发现的上游能力先加入迁移台账，不默认为首期扩容。
