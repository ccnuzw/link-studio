# 实施基线与开发批次

日期：2026-11-19。本文是本轮面向实现的工程方案；已确认产品边界见 [冻结决策](../06-决策记录/冻结决策.md)。没有运行证据的选型明确列为验证项，不将其写成已经验证的事实。

## 1. 实施范围

V1 发布基线为：本地项目 → 素材导入 → 核心画布 → 自定义 Provider 插件 → 设置/画布双入口 Agent 辅助 → 生成结果入库 → 顺序拼接 MP4 与可选 BGM。D011 明确共享引擎和核心画布助手是主线，不能只交配置助手；官方服务仍为独立后续批次。

完整短剧、营销、导演台、角色卡和分镜专属工作流统一归入 V2；V1 为这些数据保留扩展和未知节点兼容，不把占位入口作为迁移完成。共享空间与组织归入 V3。最终整体能力覆盖以 [迁移台账](上游能力迁移台账.md)逐项验收，不以版本标题或文件复制数量衡量。

## 2. 工程结构

保留现有 docs，后续建立单一 pnpm workspace，不把两仓库的根目录和 lockfile直接合并。

```text
src/main/                     Electron 生命周期、窗口、IPC、项目写入协调器
src/main/services/linkStudio/ 项目/资产/凭证/插件注册/任务/导出服务
src/preload/                  显式 DesktopAPI 域与可释放事件订阅
src/renderer/                 创作工作区及迁入的 video-canvas UI
packages/link-studio-core/    无 Electron 依赖的 schema、领域规则、序列化与状态机
packages/provider-runtime/    Host 契约、纯钩子桥接；引擎在 M0 验证
packages/agent-runtime/       共享 Pi Durable engine/store、设置/画布工具及恢复
resources/provider-plugins/   迁移的上游内置插件与来源清单
resources/media/              分平台二进制清单及许可，不将真实密钥放入资源
tests/integration/            文件系统、子进程、插件、网络与媒体验证
tests/e2e/                    Electron 用户路径验收
tests/fixtures/               合成媒体、mock Provider、项目与损坏样例
scripts/                      边界检查、许可/来源检查和构建辅助
```

Renderer 只依赖 core 的安全 DTO 和 preload 类型，不导入 main、Node 内建模块或通用 HTTP/文件能力。Main handler 接收 unknown 后经 schema 收窄；core 不依赖 Electron。Provider/媒体/Agent 工作进程不直接改项目 JSON，结果提交给 Main 的项目协调器。

| temporary-synced：临时快照已 fsync，未发布 | 旧 revision=1 | 只新增一次 revision=2 |
| snapshot-published：hard link 已发布，目录未 fsync | 本机进程崩溃恢复 revision=2 | 返回已有回执，不新增 revision |
| directory-synced：目录已 fsync，manifest 未更新 | revision=2 | 返回已有回执，不新增 revision |

SIGKILL 证明进程崩溃恢复，不等于断电/存储硬件失效试验；发布但尚未目录 fsync 时，断电结果仍可能为旧版或新版。Windows/macOS Intel/网络盘/云同步目录、窗口 owner 与 IPC 授权、创建去重、真实资产 schema 和 UI 保存均未验证，S1 必须补齐。M0-02 插件、M0-04 媒体和 M0-05 Agent 仍按原任务卡推进。
