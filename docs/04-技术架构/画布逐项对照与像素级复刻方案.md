# 画布逐项对照与像素级复刻方案

2026-11-21。原版基线为 `video-canvas@ccffac4e2f628c2b3a3655cafeffd4b38524ab22`。桌面基线为 `link-studio@d8065a0` 加本次检查时的工作树，包含进行中的助手改动。验收对象是用户打开创作画布后能看到、操作、保存、重新打开的一切，包括画布直接打开的专业编辑器、素材、任务和助手。短剧等其他页面嵌入同一编辑器时，还应回归共享编辑器，以及从画布出入这些页面时的交接行为。

## 1. 验收口径

同一初始数据、设置和设备输入，在两端应得到相同的入口、可用项、操作顺序、中间反馈、最终作品和重开结果。功能验收覆盖拒绝、取消、失败、重试和恢复。视觉验收独立比较相同状态下的布局、文字、图标、图层、光标和动效。两个维度分别通过后才能签收。Electron、IPC、本地文件、数据库和媒体处理器可按桌面架构实现。

[首期创作交互设计](首期创作交互与节点迁移.md)中的属性区、脚本生成、项目工具入口反映桌面首期规划。严格复刻以本次固定的原版实际行为为准。既有桌面专属功能可放在项目级入口，避免改变画布的菜单、占位和快捷键。原版文案、品牌或助手名称与桌面命名冲突时，单列可见差异，不能自动计入完全一致。

## 2. 功能和操作对照

### 剪线、删除键和撤销后的选区（2026-11-23）

`scripts/compare-canvas-workspace.mjs --cut-edge`（深色加 `--dark`）通过真实的固定版 Flow 和桌面项目导入入口，在同一根斜线约 37% 处点击。仅悬停无线剪按钮；选中后出现直径 36 CSS px 的剪刀，悬停扩大到 38.88。剪刀获得键盘焦点后 Enter 剪断；撤销不仅恢复线，还恢复选区，剪刀重新出现在 50% 中点。再用 Backspace 剪断、撤销、重做、撤销，两端状态相同。删除选中的单个节点或两个节点再撤销，都恢复原节点选区。画布上的向前删除键（DOM `Delete`）既不删除选中节点，也不剪线；这和 Backspace 是两种输入，导演台内部的删除规则独立。

桌面修复前，撤销剪线后只剩未选中的灰线；现在节点和连线的选区随内存撤销栈恢复，选区变化不增加一步，项目文件格式不变。Electron 交叉线用例还核对：剪上线后选下线，撤销恢复上线选区，重做回到下线选区，重开保留两条线但没有剪刀或选区。多选复制、布局、删除和打组已通过核心编辑回归；三项进行中上传删除回归也通过。

| 浅色，桌面默认启动 | 0 | 4,492 | 6,530 | 4,437 | 4,927 |

**未剪断的连线有不同的恢复规则。** 拖动文本节点后点击变形连线的 31% 处，撤销位移应选回文本、隐藏剪刀；重做位移则恢复连线选区和上一次点击的剪刀位置。桌面此前会把剪刀移回 50%。恢复历史时保留同一节点的测量尺寸后，两端原 SVG 路径保持挂载，实测浅深色重做后均为 `31.0547%`。同裁区 `redoMove` 两端分别仍有 5,004／5,091 个 RGBA 像素不同。

### 图片标注工具栏和连续派生（2026-11-23）

Electron 实测在一张 256×256 透明 PNG 上绘画、撤销、重做、输入文字、换黄笔画框，保存后保持源图选中。再次直接从源图进入编辑并保存，新节点同列下移 364（324 高 + 40 间距），名称追加 ` 2`。一步撤销同时删除第二张图和它的来源线，重做恢复。重开有三图两线，第一张派生图的实际 PNG 中仍有红色文字和黄色矩形。粗细键盘 End／Home／四次右箭头分别到 20／2／6；空内容提示不挤动工具栏。避让按绝对位置计算，考虑组框、派生图长宽比与源图垂直居中，碰撞最多下移 60 格。

`VIDEO_CANVAS_WEB=<固定版 web> node scripts/compare-doodle-toolbar.mjs --strict`（DPR 2 加 `--retina`）。同一 Chrome、两边各自的实际工具栏与生产样式；宽 1280 和 620（高均为 700）、浅深主题，整窗截图后裁出 620×142 CSS px 区域逐像素比较。工具栏宽分别为 600 和 416，高都是 40。颜色面板为 250×40，在颜色按钮下方 8 px；窄窗收起四个按钮文字但保留名称。初始、调色板、键盘 End 后的滑块焦点共 **24/24 个状态 RGBA 零差**。每端等待按钮回弹结束，连续采三张整窗图确认静止后再裁切。修复前，窄窗 DPR 1 焦点态浅色差 106 个设备像素、深色差 48 个；已对齐色点定位、圆角及滑块输入层背景。报告：`test-results/doodle-toolbar-parity-{1,2}/results.json`。此处不包含节点图片、工具条入场动画逐帧和不同引擎下的整窗像素。

**保存、删除、失败重试。** 桌面现在点击保存就退出编辑，在编码完成前追加 0% 的节点和来源线，不锁住画布。原版真实 `Flow`（仅后端 HTTP 使用本地响应）与 Electron 双端回放：PNG 编码失败均移除占位图与来源线；编码时选中占位图按 Backspace，再撤销删除，均恢复同 ID 的「上传已中断，请删除后重新上传」，没有重试按钮，不发布文件。原版上传返回 503、桌面真实暂存文件同步抛错时，均在原节点提示「上传失败，请重试」；单击重试成功，不多建节点或连线。桌面还验证慢写期间撤销建图不会被迟到结果复活；两次标注同时待保存有两张占位和两条线，完成后 ID 和落点独立，未完成时不进存档。

**导出文件对照。** 桌面标注层现在使用 React Flow 测得的节点绝对位置和尺寸，而非媒体子元素尺寸。两端以同一 32×32 PNG 底图、100% 缩放、6 px 红色矩形，从图内 (26,26) 拖到 (82,88)。原版捕获上传的实际 `doodle.png`，桌面读取项目中提交的 PNG；匹配节点视口坐标（含小数）和 DPR 2 后 **1,024 个 RGBA 像素零差**。对照条件很重要：使用不同 DPR 和不同亚像素起点时曾差 27 像素，不能把局部笔画位置相似当作同输入。复验：先跑 `tests/e2e/canvas.spec.ts` 中「图片标注在导出前」用例，再执行 `VIDEO_CANVAS_WEB=<固定版 web> node scripts/replay-reference-doodle.mjs --compare-output`；结果位于 `test-results/doodle-lifecycle/reference.json`。这是矩形样本，不代表全部原图格式或整个保存动画。

**大图缩放与中文文字。** 固定版 Flow 与桌面导入同一张 5000×2500 含透明区的 PNG，DPR 2，在 100% 下缩小一档（实测 5/6），同一位置输入两行「镜头」「转场」，再画一笔。Esc 关闭色板后焦点回到「颜色」，源节点仍选中；Esc 取消空文本不入历史。两端 Chromium 预编辑／提交共 9 个 composition 事件逐条一致，预编辑中不可撤销；确认两行后一次撤销／重做即可移除／恢复整个文字对象。固定版上传且派生节点成功加载的 PNG 与桌面项目落盘 PNG 均为 4096×2048，**8,388,608 个 RGBA 像素零差**。另断言两行文字和笔迹各自存在，底色和透明区均保留。复验：先运行桌面用例「大图缩小后中文标注」，再以相同环境变量执行 `node scripts/replay-reference-doodle.mjs --composition`；见 `test-results/doodle-composition/reference.json`。此项使用 Chromium 输入协议，不涵盖系统输入法候选窗的外观和操作，也未覆盖其他字体、倍率或动画。

### 如何判断“完全一致”

1. **同一数据。** 准备空画布、七类节点和分组的画布、含横竖图／音视频／多版输出的画布、运行中／失败／冲突的画布。固定模型能力、返回事件、媒体、时钟、语言和用户设置。真实文件导入、编码、持久化和重开另跑集成链路，防止模拟结果掩盖差异。
2. **同一动作。** 用同一串按键、指针坐标、拖拽路径和时间间隔驱动两个实际页面。每一步比可用菜单、选区、焦点、视口、节点、边、提示和任务。输入错误、撤销、取消、重试要能独立复现。比如同样按两次截帧再确认，最终必须得到相同的两张图片、来源和位置。
3. **同一画面。** 以实际 Electron 的 Chromium 版本、字体、OS、GPU、DPR、内容区尺寸和主题固定参考环境。建议首组 1440×900、1280×800、1024×700，DPR 1/2、深浅色。分别跑全新设置和已有设置。用原版构建在同一渲染器获得可复现基准，再与正常浏览器和真实桌面产物交叉验证。
4. **严格像素验收。** 原版先连续采三次验证自身稳定性。在固定环境、确定性静帧下，比较同尺寸 RGBA，要求不同像素数为 0，同时比关键元素边界、命中区和文本断行。出现 1px 偏移也登记。动图、视频、3D、光标和进度按固定帧、固定时刻或确定性事件采样。无法稳定复现的状态记待验证，禁止用统一相似度、整块遮罩或桌面截图反写原版基准替代验收。
5. **分别记录平台。** 不同系统的字体栅格和媒体解码可有实际差异。每个支持的平台都在本平台与原版配对；保留原生窗口栏和文件选择器边界说明。品牌、原生弹窗、桌面新增入口等任何可见例外必须逐项列出，有例外时报告实际覆盖范围。

### 生成方式、媒体连线与新建落点

- **生成方式。** 视频模型提供多种方式时显示独立的胶囊栏；单模式、缺少模型和放大编辑时不显示。连接图片、视频、音频、角色卡或已有手动参考后，文生视频不可选，不以是否已经得到成片来判定。断线不重置方式：已选图生可以变为禁用，需手动切回文生。缺参考的按钮可聚焦并显示原因，不能用 Enter 选中；任务忙时则原生禁用。选中滑块使用每个节点独立的布局动画。
- **接线。** 端口和节点体、拉到空白处新建、提示词引用与多选建节点按下游可用模型判断。当前方式已能接就保留，否则优先能接的全能参考。已上传的素材不接入线；分镜来源线不作媒体参考。图片节点同时支持文／图生时可接入第一根图片线；音频节点只在模型支持图片参考时收图片。模型清单未到时不凭空禁线。`scripts/compare-video-modes.mjs` 直接运行两端规则，视频方式、禁用理由与接线共 **512** 项相同，图片和音频目标另有 **280** 项相同。这不是 792 次端到端回放。
- **桌面操作与请求。** Electron 验证从空图片端口拖到空白处，文生图模型菜单项禁用、支持图片参考的音频模型可选，快照含正确的来源线。双模式视频接线后不能切文生，带原图的 multipart 请求和断线后显式切文生的无图 JSON 请求分别到达本地测试服务；单模式分镜请求保留手动参考。新建卡片按视口宽度 50%、高度 40% 放置默认 576×324 框，实测其中心偏差小于 1 CSS 像素。
- **像素。** 同一 Chrome、1200×800、DPR 1，裁取 246×36 方式栏。空参考、已连参考、切换全能后的稳定帧、悬停可选项、键盘焦点、任务忙，浅／暗各六态共 **12 张，每张 0 / 8856** 差异像素；栏和三个按钮的矩形也相同。产物在 `test-results/video-mode-parity/`。`scripts/compare-media-prompt.mjs` 复验上节模型下线提示，两主题均为 **0 / 18144**；内联面板／放大面板仍差浅色 **24／32**、暗色 **25／26** 像素；两种面板内的菜单分别仍差浅色 **121／50**、暗色 **446／0** 像素。不据此签收整屏、动效逐帧或短窗口的滚动行为。

- **回归。** 类型检查、构建、307 项单元测试和最终串行的 7 项 Electron 回放通过。此前一次 S4 用例打开文本编辑器时焦点断言失败，独立于像素对照运行整组后通过；未删减焦点断言，也未将单次复跑视为排除了焦点竞态。
