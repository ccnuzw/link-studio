# 短剧人物拆解、任务恢复与稿纸对标方案

2026-11-23 · 对照 `video-canvas` 与桌面端 `link-studio`。下列回放来自现有项目快照，修复项与视觉指标供后续实施验收。

## 同模型为何出现不同的卡片

| 离线回放输入 | 原项目解析器 | 桌面解析器 |
| --- | --- | --- |
| 从桌面项目「哑妃1-30」当前快照读取的 `characters_md` | 上官家、宫中主子、宫人及侍从三张卡，各有 6、5、12 条备注 | 相同 |
| 按参考图重建的最小样本，`## 主要人物` 下分别写 `- **上官淳儿**：介绍甲。` 和 `- **关景恒**：介绍乙。` | 两张独立人物卡 | 相同 |

两端的 `parseCharacters` 都靠预设标题词识别分组。遇到「上官家」这样的标题，它会将标题当成人物，将下面的人名列表收进备注。截图里的「主要人物」和冒号格式恰好能被识别。原项目卡片组件只把解析好的角色按组排版。23 是列表条目数，其中有「王氏、云氏」这样的合写条目，不能直接当成独立人物总数。

研读、分集规划草稿、分集剧本草稿、资产拆解草稿、资产提示词草稿的内置模板逐文件一致。研读模板要求人物资料与有依据的阶段信息，允许多种 Markdown 写法。两次历史生成缺少完整请求对照，无法确定模型为何分别选用了两种写法。已经能独立复现的是旧稿的解析错误。另有可查证的请求差异，需要分别处理。

| 环节 | 已查到的差异 | 修复与验证方式 |
| --- | --- | --- |
| 研读取样 | 两端都侧重开篇并保留后段样本。桌面端先扣模板开销，小上下文下可能取得不同片段 | 对同一本书固定模型版本、上下文预算，比较原文区间、抽样哈希和最终输入长度，保留最终超限检查 |
| 模型请求 | 原项目以单条用户消息提交短剧任务，按模型能力设输出预算。桌面复用模型测试通路，可能附加 Agent 系统提示，未配置上限时回落到 2048 | 分开「Agent 模型可选」与「继承 Agent 对话指令」。对齐短剧请求的消息角色和预算；区分输出截断、无效结构、网络失败，对可恢复的错误有限重试 |
| 分集规划与剧本 | 项目可选内置、技能或自定义提示词。剧本还依赖本集原文范围、前集结尾、钩子、悬念和既有人物 | 做从任务入口到模型调用的离线请求夹具，分别断言研读、规划草稿与格式化、逐集剧本、资产拆解与补词的有效模板、拼入的变量及版本。运行诊断记录来源、哈希、长度、停止原因，便于追溯 |
| 资产拆解 | 原项目在任务入队时冻结既有角色／资产，拆解时作为 `assets` 传入。桌面只给剧本任务冻结 `known_cast`，拆解调用缺这份输入 | 拆解也在入队时冻结，新任务能看到最新资产，同一任务重试复用原快照。逐项对齐原文来源、梗概与集信息，并验证跨集角色复用。此处影响资产拆解，发生在首次研读之后 |

## 优先修复旧项目

1. **从原稿恢复人物卡。** Markdown 继续作为编辑和保存的依据，读取时派生「分组 → 人物 → 别名、资料、阶段、原文备注」。结合标题下的列表形态区分家族分组、人名和资料名，兼容中文／英文冒号、破折号、括号别名和多段介绍。旧项目重新打开即可重排；编辑原稿后即时重算。含混的合写、陌生字段与自由段落保留原文，可在原文视图核对。
2. **分别定义传记阶段和画布造型。** 同一人物的别名放在姓名下，有原文依据的年龄、身份或时期在卡内分段显示。需要不同视觉表现时，画布拆为同一角色的不同造型，沿用原项目的 `look` 标识和分集关联。验收包括同人多名、童年／成年双阶段、无阶段资料、合写条目四类，检查原文、卡片和画布对应关系。新稿可约定稳定的 Markdown 示例，保留用户自定义提示词的内容和来源。
3. **恢复已有资产的空提示词。** 样本第 1 集已锁定，已写入 6 个人物、1 个场景、2 个道具，拆解任务失败，9 个节点均未写入提示词。保存的 `AGENT_TEST_HTTP_FAILED` 仅能定位到调用失败。原项目把未完成的提示词交给 `asset_prompts` 后续任务。桌面应在资产页和任务详情显示「9 个资产待补提示词」及「继续补写」，以原节点 ID 补缺。估价、执行、按钮可用条件使用同一份待办集合，空集合为零。已完成的集保持锁定，手工改过的文本优先，重复点击复用进行中的任务。模拟补写一半时失败、重启、重试和同时手工编辑，核对节点、连线和已完成结果均可继续使用。
4. **标题旁增加项目任务进度。** 沿用原项目任务胶囊的位置与展开方式，保存状态独立显示。跨总览、剧本和资产页显示当前步骤、涉及集数或已完成数；并发任务按项目汇总，展开可定位分集或失败资产并继续。重开项目从持久化任务恢复状态。无法计算分母时显示阶段名，空闲时收起。单卡出图、出视频保留卡内反馈。

## 五张参考图的复刻基准

以下数值来自原组件的 CSS 像素。字号和换行用相同字体、窗口宽度和缩放比对拍。

| 对照位置 | 桌面需要复刻的细节 |
| --- | --- |
| 图 1 · 人物网格 | 内容区最大 1040px，组按原文首现顺序排列。组间 28px，组名 12px、字距 0.12em，卡片间距 12px。原项目在 768px 断点从单列变固定双列。替换桌面随空间自动增列的排法，补齐右上「卡片／原文」图标切换及选中态 |

| 图 3 · 分集剧本 | 22px 展示字体标题，锁定胶囊与标题同行，说明条置于纸张外。纸内左侧 36px 处画 1px 装订虚线，小屏隐藏。宽屏保留 208px 吸顶页边栏，含场次跳转、梗概、钩子、悬念与对应原文，按来源显示章节或其他原文单位。覆盖有场次、无可识别场次、待生成、生成中和已锁定状态 |

| 图 5 · 人物文字卡片 | 卡内边距 20px，原项目构建产物实测圆角 22px，纵向间距 16px。圆形人物图标底 44px、图标 20px；姓名展示宋体 18px／900，别名 12px，字段名 12px／24px，字段值及备注 14px／约 23px。字段名与内容排两列，长中文自然换行。正文沿用 Geist／苹方回退，避免整块正文继承标题宋体 |

只将稿纸、人物卡、编辑器用到的纸面、正文、次要文字、工具按钮和锁定提示映射到现有明暗主题变量。逐态核对 hover、选中、焦点、禁用、失败、只读和文本选区，尤其检查深色纸面上的小字、提示词预览、长文本与相邻面板的边界。

## 实施顺序与验收

| 顺序 | 完成标志 |
| --- | --- |
| 1 · 旧稿与人物解析 | 两端实际解析器的回放结果作为基线。新版能在离线打开旧项目后按人物成卡，保留 23 条来源记录及其分组；别名与阶段可追溯。编辑并重开后，卡片和原文仍一致 |
| 2 · 请求对齐与资产恢复 | 用固定模型响应检查每一阶段的实际请求和错误分类。对失败项目副本执行补写，检查待补集合从 9 到 0，中断后只处理剩余项；在画布逐卡打开可见对应提示词。零待办、已手改、节点被删及重复点击都有确定结果 |
| 3 · 项目任务状态 | 从开工、切页、失败、继续到完成回放最短操作链。重启时能从项目记录恢复进度，分集和资产入口都能定位到同一任务 |
| 4 · 视觉与交互 | 用相同 Markdown 和资产夹具对拍原组件与桌面组件，覆盖明暗主题、1024px／1440px 窗口和窄于双列断点的状态，抽查 DPR 1／2。对齐字号、行高、换行、列数和纸面层次；验证场次跳转、锁定只读、工具栏选中、保存冲突，以及长文时的滚动归属。对拍与回放采用无头环境 |
