# Link Studio 冻结决策

本文件记录对话中已明确的产品方向。具体接口、任务状态、积分和同步语义仍需后续规格化。

## D001 以视频创作为产品主线

- 状态：已冻结
- 日期：2026-11-19
- 背景：在以 Fynvra 为底座迁移，或将 video-canvas 桌面化之间选择。
- 备选方案：
  - A. 以 Fynvra 编程工作台为主，把视频业务作为功能模块：可复用更多桌面能力，但产品主导航和核心领域偏离创作。
  - B. 以 video-canvas 视频创作为业务底座，桌面化并选择性吸收 Fynvra：保留创作主线，桌面基础设施需要整合。
- 决定：采用 B；Link Studio 是视频创作生产工具，不是编程工作台。
- 理由：用户明确选择视频创作为核心；video-canvas 已有画布、生成、分镜、导演台等领域能力。
- 影响：
  - 功能：产品主导航、项目模型、画布、资产、生成任务和媒体导出。
  - 接口：桌面创作 API 与官方服务 API。
  - 数据：本地视频项目和资产，不采用 Fynvra 会话作为项目权威源。
  - 错误码：不适用：接口错误码将在 API 契约阶段定义。
- 落实：
  - [x] 更新产品与架构蓝图。
  - [ ] 建立 V1 功能需求和验收标准。

## D002 本地优先项目与双模型来源

- 状态：已冻结
- 日期：2026-11-19
- 背景：需要同时支持官方模型商业化和用户自行配置的模型，并保持桌面创作属性。
- 备选方案：
  - A. 仅官方模型：商业与权限控制集中，但无法满足用户自定义/本地模型需求。
  - B. 官方模型 + 本地自定义模型：覆盖商业模型和本地灵活性，但需要分离凭证、任务执行和计费。
- 决定：采用 B；项目默认本地保存；官方模型和自定义模型共用创作体验，但执行及结算通道分开。
- 理由：用户明确要求保留两种模型来源；本地项目应可独立于账号使用。
- 影响：
  - 功能：模型选择、任务中心、登录、资产管理、项目保存。
  - 接口：官方服务任务接口；本地 Provider Runtime 接口。
  - 数据：本地任务 journal、官方任务 ID、项目资产引用；密钥不得进入项目文件。
  - 错误码：不适用：错误码由后续任务/API 规格定义。
- 落实：
  - [x] 在产品蓝图区分官方/自定义执行。
  - [ ] 冻结官方任务服务端代理和积分结算规则。
  - [ ] 冻结本地 Provider 协议范围和安全策略。

## D003 本阶段不提供工作室自托管和工作室 Provider 层

- 状态：已冻结
- 日期：2026-11-19
- 背景：当前产品以官方服务与本地桌面端为主，不希望增加工作室模型作为第三种来源。
- 备选方案：
  - A. V1 支持工作室自托管和工作室渠道：面向企业更灵活，但显著增加部署、密钥、升级和支持矩阵。
  - B. 官方服务统一提供账号/官方模型；桌面端提供用户自定义模型：当前路径简单，未来可在官方后台增加组织策略。
- 决定：采用 B；当前不支持工作室自托管，不设独立“工作室模型”来源。未来组织作为官方服务端的身份、权限、额度和共享空间层评估。
- 理由：用户明确暂不需要自托管和工作室模型；组织管理计划属于未来官方后台能力。
- 影响：
  - 功能：部署、模型目录、账号、权限、积分、共享空间。
  - 接口：官方服务 API；不提供自托管控制面接口。
  - 数据：当前不定义组织/工作室数据表。
  - 错误码：不适用。
- 落实：
  - [x] 文档中将组织列为后续演进，不作为当前模型来源。
  - [ ] 规划组织能力时重新评审本决策。

## D004 首阶段先交付本地自定义模型

- 状态：已冻结
- 日期：2026-11-19
- 背景：官方模型的客户端请求路径、凭证边界、积分冻结/结算和失败退款语义尚未形成可执行设计，不能阻塞桌面端迁移启动。
- 备选方案：
  - A. 首阶段同时交付官方与自定义模型：用户能力完整，但会把未决的资金和外部调用风险带入首期。
  - B. 首阶段交付本地项目与自定义模型，官方模型后续单独设计：先验证桌面创作和本地 Provider 闭环，不预设官方消费技术路径。
- 决定：采用 B；允许未登录用户使用本地项目和自定义模型。官方模型的执行与结算方式保持待决。
- 理由：用户明确选择自定义模型先行、允许未登录使用，并要求分阶段迁移。
- 影响：
  - 功能：V1 本地项目、画布/资产、本地 Provider、生成任务、媒体输出。
  - 接口：首阶段只冻结桌面 IPC 和本地 Provider 契约；官方服务接口后续定义。
  - 数据：个人 Provider 凭证保存在设备安全存储，不进入项目文件。
  - 错误码：不适用：在功能规格中分别定义。
- 落实：
  - [x] V1 首阶段范围调整为本地自定义模型闭环。
  - [ ] 完成本地 Provider 和生成任务技术设计。
  - [ ] 官方模型进入开发前单独冻结执行、结算和退款契约。

## D005 自定义 Provider 采用可扩展插件并支持 Agent 辅助

- 状态：已冻结
- 日期：2026-11-19
- 背景：用户需要快速迁移现有 `video-canvas` Provider 生态，同时支持新协议持续扩展，并允许内置 Agent 帮助配置插件。
- 备选方案：
  - A. Provider 适配全部硬编码进桌面应用：运行安全直观，但新增协议必须发版，无法吸收上游插件生态。
  - B. 使用可扩展插件；插件只描述请求构造/响应解析，受控宿主负责网络和密钥；Agent 可创建/修改草稿，人工也可编辑：保留扩展性并将插件作者代码与凭证隔离。
  - C. 允许插件任意 Node.js 执行：扩展自由度最大，但插件可直接访问文件、密钥和网络，风险不可接受。
- 决定：采用 B 的产品方向：可扩展 Provider 插件，内置 Agent 辅助配置，人工配置同样支持。
- 工程提案：吸收上游纯函数钩子、版本化 manifest、宿主代发请求和统一结果契约；插件无直接网络/文件/密钥权限。Agent 根据文档生成草稿、运行静态校验和 mock 测试，用户通过启用动作确认具体版本。隔离实现、版本绑定和测试交互属于设计建议，不作为用户已经逐项确认的细节。
- 理由：用户明确要求可扩展 Provider 插件，并要求 Agent 配置和人工配置两种方式；隔离宿主执行可以避免插件直接持有凭证。
- 影响：
  - 功能：V1-FR-004、V1-FR-005，以及 Agent 插件作者工作流。
  - 接口：Provider 插件 API、沙箱 Runtime、宿主网络能力契约。
  - 数据：插件 manifest/源码/版本/启用状态；凭证由独立 SecretStore 引用。
  - 错误码：插件校验、运行时超时和权限拒绝错误待接口契约定义。
- 落实：
  - [x] Provider 配置规格改为插件管理及 Agent/人工双入口。
  - [ ] 定义 Link Studio 本地插件 API 版本和兼容层。
  - [x] 建立沙箱、宿主网络策略、密钥注入和 Agent 启用的 Draft AC。

## D006 导入素材默认复制到项目

- 状态：已冻结
- 日期：2026-11-19
- 背景：项目默认本地保存，且未来可能创建共享空间；引用外部源文件会使项目易因移动/删除而断链。
- 备选方案：
  - A. 默认复制到项目，并提供明确的外部引用模式：项目可携带，但会增加磁盘用量。
  - B. 默认引用源文件：省磁盘空间，但项目完整性依赖外部路径。
- 决定：采用 A。导入默认复制到项目资产库；高级选项允许引用外部文件，引用状态必须可见并可重新定位。
- 理由：保证默认项目可迁移、可恢复；用户已明确选择复制优先。
- 影响：
  - 功能：V1-FR-002、V1-FR-003、V1-FR-005、未来共享空间。
  - 接口：资产导入 IPC 的默认 importMode 为 copy。
  - 数据：项目 Blob 是默认权威副本；外部引用必须标记 reference mode 和 source locator。
  - 错误码：不适用：沿用资产导入错误矩阵。
- 落实：
  - [x] 素材规格默认模式调整为 copy。
  - [x] 补齐复制中断、重复 hash 和引用丢失的 Draft AC。

## D007 应用退出时保留可恢复的生成任务

- 状态：已冻结
- 日期：2026-11-19
- 背景：本地 Provider 可能运行长任务；应用关闭不应把任务悄悄丢失，也不能在结果不明时盲目重复计费调用。
- 备选方案：
  - A. 退出时等待/请求取消/退出；重启后查询支持恢复的任务，不支持或结果未知的任务进入 unknown。
  - B. 退出立即杀死所有任务，重启后由用户手动重试：实现简单但丢失已受理任务状态。
- 决定：采用 A。退出前提供等待、尝试取消或退出并稍后恢复的选项；重启时对有 providerTaskId 且插件支持查询的任务恢复轮询；没有可靠查询能力或提交结果未知时标记 `outcome_unknown`，不自动重发。
- 理由：用户明确选择 A；避免无声丢任务及重复收费。
- 影响：
  - 功能：V1-FR-005、应用生命周期和退出确认。
  - 接口：Provider submit/query/cancel capability，JobStore 恢复 API。
  - 数据：持久化 jobId、providerTaskId、插件版本、状态、最后轮询时间和恢复策略。
  - 错误码：不适用：使用任务状态和错误键。
- 落实：
  - [x] 生成任务规格补充退出/重启恢复规则。
  - [x] 在 Provider 插件与 Agent 配置设计中增加恢复行为矩阵。

## D008 首期导出支持顺序拼接 MP4 和可选 BGM

- 状态：已冻结
- 日期：2026-11-19
- 背景：首期需要形成可交付作品的视频生产闭环，明确基础合成范围。
- 备选方案：
  - A. 支持视频镜头按顺序拼接为 MP4，并可添加 BGM：能交付基础作品，需要本地合成链路。
  - B. 只导出单个生成文件：实现较少，但不能形成多镜头成片。
- 决定：采用 A；首期导出支持视频镜头排序、顺序拼接为 MP4 和可选 BGM。不包含完整多轨非线性编辑。
- 理由：用户在第 4 项选择 A。
- 影响：
  - 功能：V1-FR-006。
  - 接口：有序视频资产列表、可选 BGM 引用和导出配置。
  - 数据：持久化导出配方快照，不能仅依赖运行时选择状态。
  - 错误码：沿用媒体导出错误矩阵；具体编码与音频混合规则为待验证的工程设计。
- 落实：
  - [x] 更新导出规格、技术设计和验收设计。
  - [ ] 验证 FFmpeg 构建、混合素材归一化和音画同步。

## D009 同一项目只允许一个可写窗口

- 状态：已冻结
- 日期：2026-11-19
- 背景：本地项目需要防止多窗口或多实例自动保存互相覆盖。
- 备选方案：
  - A. 同一项目单写窗口：重复打开定位已有窗口，跨实例占用时拒绝第二个可写打开；不同项目可分别打开。
  - B. 同一项目允许多个窗口并行编辑：需要额外合并和冲突交互。
- 决定：采用 A；V1 同一项目只允许一个可写窗口，不提供同项目并行编辑。后台任务与自动保存仍由同一项目写入协调器串行提交。
- 理由：用户在第 5 项选择 A；减少静默覆盖风险和首期协作复杂度。
- 影响：
  - 功能：V1-FR-001、V1-FR-003、V1-FR-005、V1-FR-006。
  - 接口：项目打开返回已打开/已占用状态；写入需有效 owner 和 revision。
  - 数据：进程间项目占用记录或等效系统锁；以规范化目录身份识别项目，不能仅比较 projectId。
  - 错误码：新增项目占用错误键；具体锁原语与崩溃恢复机制需按平台验证。
- 落实：
  - [x] 更新本地项目规格、技术设计和验收设计。
  - [ ] 验证路径别名、双实例竞争和异常退出后的锁恢复。

## D010 按批次实施并统一后续创作域归属

- 状态：已冻结
- 日期：2026-11-19
- 背景：用户授权补齐面向实现的设计；现有 V1 后续阶段与 V2 对短剧/营销/导演台范围重叠，缺少清晰的开工停止线。
- 备选方案：
  - A. 完整迁移全部域并细写 V2/V3 后才开工：整体文档多，但验证和首版交付后移。
  - B. 本地核心闭环先实施，建立全量迁移台账；完整创作域归 V2，组织/共享归 V3，各批开发前补其契约。
- 决定：采用 B 的实施方案。M0 技术验证可以先启动，S1～S5 逐批实现 V1 本地闭环；官方服务为独立后续增量，不阻塞本地版。V2/V3 当前只维护能力范围、依赖和进入条件。
- 理由：本轮由助手在用户授权完善实施设计的范围内统一分期；保留用户已确认的整体迁移目标，不增加首期范围或删除后续能力。
- 影响：
  - 功能：V1-FR-001～006；后续版本不提前编号。
  - 接口：按当前开发批次细化与验证，不要求未来同步/计费接口先冻结。
  - 数据：首批本地 schema 与扩展保留策略；后续按版本迁移。
  - 错误码：首批 API 采用统一字符串错误键，取代各处待定数字编号。
- 落实：
  - [x] 统一路线图与版本边界，补工程基线、迁移台账、首批数据/API 和验收设计。
  - [ ] M0 实际验证并建立可执行工程命令；通过后按批次更新规格门禁。

## D011 完整迁移双入口 Agent 与主要创作能力

- 状态：已冻结
- 日期：2026-11-19
- 背景：用户要求完整迁移设置/画布内置 Agent 的工作机制与交互，以及所有主线与主要功能；仅桌面不适用或与已确认设计冲突者例外。
- 备选方案：
  - A. V1 仅 Provider 配置助手，画布 Agent 整体后置：不满足当前要求。
  - B. 共享 durable 引擎、设置助手和核心画布助手进入 V1，专业域 Agent 随对应域分期迁移。
- 决定：采用 B；修正 D010 及先前工程方案中“完整画布助手整体延后 V2”的解释。完整迁移覆盖上下文、工具、审批/变更单、安全密钥、插话/恢复、watch、撤销、技能/code-mode 和运行反馈，不以聊天框或插件生成替代。

- 影响：

  - 接口：共享 Agent API、Tool Gateway、模型流/tool calling、配置变更单与项目 mutation。
  - 数据：本机 Agent SQLite、scope、审批/工具回执/watch 与项目/配置的恢复对账。
  - 错误码：Agent、设置变更与画布工具错误族，具体 union 在对应批次冻结。
- 落实：

## D012 产品与内置 Agent 命名

- 状态：已冻结
- 日期：2026-11-19
- 背景：用户在启动开发和初始化仓库前明确指定产品中文名与内置 Agent 名称。
- 备选方案：不适用；本条直接记录用户指定命名，不另作品牌选型。
- 决定：产品中文名为“灵可”，英文名保持“Link Studio”；仓库和工程目录名为 `link-studio`；内置 Agent 名为“小灵”。设置和画布是小灵的两个工作入口，共享引擎及各自工具权限，沿用 D011 的边界。

  - 数据：不修改既有项目 schema、稳定 ID 或 Provider 名称。
  - 错误码：不适用；本条不新增错误语义。
- 落实：
  - [x] 更新仓库 README、文档入口、产品概览和 Agent 设计的命名引用。
  - [ ] M0 创建应用时落实展示名称，后续功能界面统一使用“小灵”。
