## 伪代码

```text
FUNCTION startExport(input):
  IF source refs invalid: RETURN EXPORT_SOURCE_MISSING           // B06-01
  IF target exists AND overwrite not confirmed: RETURN TARGET_EXISTS // B06-02
  freeze ordered assets and optional BGM, pin input versions; reject unsupported media // B06-06
  normalize video geometry/fps and audio format; add silence for clips without audio // B06-07
  IF BGM selected: mix using recipe; constrain audio to composed video duration // B06-08
  persist export job and spawn worker without shell             // B06-03
  IF cancelled or worker fails: clean temp; mark terminal       // B06-04
  IF output validation fails: clean temp; RETURN MEDIA_INVALID   // B06-05
  atomically commit output and mark succeeded
  register output through project writer without replacing newer canvas state // B06-09
  release pinned input references on every terminal path
```

## 并发控制

同一 exportId 状态更新使用 CAS；同一目标路径的并发导出通过 Main 目标锁序列化，第二项任务需重新确认覆盖。

当前任务使用不可变配方；媒体计算不占用项目短事务锁。项目仍由 D009 的单一 owner 协调输出入库；所有输入在导出期间增加使用引用，取消/失败也需释放。

## 顺序合成方案

FFmpeg 在独立媒体进程中读取有序输入，按配方统一分辨率、帧率、像素/音频格式，再使用受控滤镜完成顺序拼接。画面按比例缩放加留边；无音轨片段补静音，以视频时长确定音频对齐。首期以统一转码作为兼容基线，流复制快路径仅在经验证输入完全兼容时考虑。

MP4 容器已冻结；推荐验证 H.264/AAC 作为首个编码配置，其构建许可、平台可用性和播放器兼容性尚待确认。BGM 不改变视频长度：长则截断、短则静音补齐尾部，不因音频较短提前结束视频；源音/BGM 音量和混合策略保存在配方中。测试需验证输出帧序、总时长、音轨和同步，不能仅以 FFmpeg 返回码为成功依据。

## 事务边界

转码过程不在文件提交事务内。输出完整后校验 hash/容器，再使用平台验证过的原子 rename；目标覆盖的备份/替换方案待 OS 实测。

## 幂等与重试

导出任务可重新执行；新任务必须新 exportId 和临时文件。提交最终文件需 exportId 幂等，避免重复覆盖。

## 外部调用与补偿

FFmpeg 是本地子进程。设置运行超时、取消信号、stderr 轮转上限和退出码映射；Worker 崩溃后只清理本任务临时路径。

## 安全与日志

- 使用绝对可执行文件路径和 argv 数组，不拼接 shell。
- 输入路径由 Main 基于 Asset ID 解析，不接收 Renderer 任意路径。
- 输出目录使用系统对话框授权。
- 记录 FFmpeg 版本、参数白名单 ID 和错误类别，不记录用户媒体正文。

## 发布与回滚

- FFmpeg 二进制按平台/架构打包；审查 LGPL/GPL 和构建选项。
- 检查 macOS 签名、公证、Windows SmartScreen/杀软和安装包体积。
- 回滚后未完成导出标记为 failed/retryable，不自动覆盖成品。

## M0-04 实现基线与待接入边界

实现位于 `packages/media-runtime/src/{composition,probe,process}.ts`。当前是受信 Main 内部服务，不接受 Renderer 任意路径；S5 仍需通过资产解析和 outputTargetToken 授权后调用。

### 编码与音频

- macOS arm64/APFS；源码构建 FFmpeg/ffprobe 7.1.3，固定下载地址、SHA-256 与 configure 见 `resources/media/build.json`；禁用自动发现/GPL/nonfree/version3/网络，仅有 file/pipe 协议，使用 H.264 VideoToolbox（allow_sw=1）与 FFmpeg AAC，不依赖 x264 或 Homebrew。VideoToolbox 初始化失败如实失败，不偷偷切换成其他编码。
- `hd-720p`：1280×720、30fps、视频目标码率 4Mbps；`m0-360p`：640×360、30fps、1.2Mbps，仅作轻量测试。两者输出 yuv420p、AAC 192kbps / 48kHz / stereo、MP4 faststart。VideoToolbox 属目标码率方案，不承诺精确恒定码率。
- 输入按指定顺序统一转码、保持比例 scale/pad 留黑边；本轮合成样例为方形像素 SDR。旋转/非方形像素/HDR/VFR/损坏时间戳等仍需专项测试，不承诺全部媒体矩阵。
- 以每段视频流 duration 定义片长；音轨按段重置时间、补静音并裁齐，无音轨直接生成静音；长源音不延长视频。BGM 默认不循环，长则截断、短则补静音；源音 gain=1、BGM gain=0.25，允许 0～2。amix normalize=0，极端高增益仍可能削波，后续 UI 应提示；不声称响度标准化。

### 输入、提交与终止

- 调用时深拷贝输入参数；将已打开的普通文件流式复制到本任务私有 sibling 临时目录，复制期间校验源 size/mtime/ctime、记录 SHA-256，随后只读取副本。原文件之后变化不影响本次合成；这不是项目资产 pin/journal 实现，也不承诺外部攻击者竞争路径时的完整 fd 级沙箱。
- 现有目标始终返回 `EXPORT_TARGET_EXISTS`，当前内部 API 不提供覆盖开关；未来覆盖确认/备份事务另接入。目标同目录临时成片经 ffprobe 类型/尺寸/音轨/总时长及视频/音频各流时长校验，并完整解码检查，再 hash、fsync，以 hard link 独占发布，最后 fsync 父目录。目标被其他写入者抢先创建也不会覆盖。
- 发布之前取消/失败只清理任务目录；hard link 是可见提交点，之后不再因迟到取消删除成品。发布后目录 fsync 失败返回 `EXPORT_COMMIT_UNKNOWN`，须核对目标，不自动重试覆盖。清理异常当前尽力处理，崩溃遗留目录仍需后续任务恢复/诊断回收。
- 同进程同规范路径用目标集合拒绝并行；跨进程终态独占发布依靠文件系统，不宣称跨进程任务锁或覆盖审批已完成。若目标目录身份变化，拒绝提交。
- spawn argv、shell=false、stdin 关闭；总任务默认 120 秒，probe 最长 30 秒。取消先 SIGTERM，1 秒后 SIGKILL，等待 close 才返回/清理。stdout/stderr 各最多 1MiB，不向用户返回原始路径/媒体日志；进度按 out_time_us 解析，回调异常也停止子进程。
- 工程 spike 上限：最多 16 段、每输入 1GiB、总片长 600 秒、输入像素数至多 3840×2160、输出 2GiB；磁盘预检包含输入副本+输出估算与余量。FFmpeg 单次分配 max_alloc=64MiB；子进程 RSS 每 100ms 采样，超过 512MiB 停止，可能超调，不是硬内核配额；VideoToolbox/GPU 内存未计入。真实 ENOSPC、断电、异常退出后的恢复和攻击性媒体仍需后续专项验证。
