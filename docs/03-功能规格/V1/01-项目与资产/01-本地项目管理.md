## 目标

创作者无需登录即可在本机创建、打开、保存并恢复 Link Studio 项目，项目数据不依赖云端服务。

## 功能边界

包含：本地项目创建、打开、最近项目、重命名、保存、关闭、损坏提示和恢复入口。

不包含：共享空间、跨设备同步、多人并发和云端备份（V3）。

## 需求说明

### 用户故事

作为创作者，我希望项目在本机保存并在重启后恢复，以便离线继续创作。

### 业务规则

1. 创建、打开和编辑本地项目不要求登录（D002、D004）。
2. 项目正文与应用全局设置分开保存；项目格式必须有 schema version。
3. 写入不得直接覆盖唯一有效快照；失败后保留可恢复版本。
4. 最近项目列表不得保存项目媒体正文或供应商密钥。

### 主流程

1. 用户选择新建项目并填写名称、位置。
2. Main 校验位置、创建项目结构和初始 manifest。
3. Renderer 打开项目并订阅保存状态。
4. 用户关闭项目时等待必要写入完成，失败则提供重试或取消关闭。

### 异常与边界

- 目标路径不可写、空间不足或文件损坏时不报告成功。
- 已打开项目被外部移动/删除时停止写入并提示重新定位。
- 应用崩溃或强制退出后使用最后一个有效快照/日志恢复。
- 同一项目只允许一个可写窗口（D009）；同一实例重复打开时激活已有窗口，另一实例占用时拒绝可写打开并提示关闭原窗口。
- 不同项目允许分别打开。占用识别基于规范化目录身份，防止通过路径别名绕过；项目副本不能仅因 projectId 相同就被视为同一目录。
- 崩溃恢复需确认原持有者已退出后再取得所有权，不能仅凭锁文件时间或心跳超时抢占。

### 页面与交互

启动页提供新建、打开和最近项目；项目关闭/退出时展示保存中、已保存或保存失败状态。位置选择使用系统对话框。

## 接口契约

### 接口清单

S1 接口采用 `projects.create/open/openRecent/listRecent/getState/rename/flush/close/removeRecent`，系统目录选择由 dialogs 域提供；字段、响应和错误统一见 [桌面 API](../../../04-技术架构/桌面API与任务契约.md)。

### 请求字段

| 字段 | 位置 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- |
| name | create/rename | string | 是 | trim 后 1～100 码点，拒绝控制字符与路径分隔符 |
| directoryToken | create/open | opaque string | 是 | Main 对话框创建，绑定窗口与用途，不接收任意路径 |
| projectHandle | 当前会话操作 | opaque string | 是 | Main 签发且绑定当前窗口、owner 和项目目录 |
| operationId/expectedRevision | 项目变更 | UUID/integer | 是 | 幂等 ID 与快照修订，规则见公共 API |

### 成功响应

返回 ProjectSession 安全 DTO：projectHandle、projectId、name、schemaVersion、revision、recoveredFromPrevious；重复打开可返回 focusedExisting，不泄漏 owner 或任意目录写权限。

### 错误矩阵

| 错误键 / code | 场景 | 用户提示 |
| --- | --- | --- |
| PROJECT_PATH_DENIED | 目录未授权或越界 | 选择一个可访问的项目位置 |
| PROJECT_CORRUPT | 无有效快照可恢复 | 项目无法读取，可尝试恢复副本 |
| PROJECT_SAVE_FAILED | 写盘失败 | 保存失败，项目数据仍保留 |
| PROJECT_CONFLICT | 修订号冲突 | 项目已更新，请重新读取后保存 |
| PROJECT_IN_USE | 项目已被其他实例占用 | 项目已打开，请先关闭原窗口后重试 |

错误码直接使用字符串键，不再分配数字。完整错误集见桌面 API，包括名称/目录存在、token、schema 和幂等请求错误。

## 数据与事务

### 读写数据

| 数据 | 操作 | 字段 |
| --- | --- | --- |
| Project Manifest | R/W | 可重建发现信息，不是事务提交点 |
| Recent Projects | R/W | projectId、lastOpenedAt、displayPath |
| ProjectState | R/W | projectId、schemaVersion、revision、parentHash、commitHash、assets、canvas、operationReceipts |
| Project Ownership | R/W | 规范化目录身份、owner token、实例标识；锁不作为共享项目正文 |

### 约束与事务

- manifest 不保存任何访问令牌或 Provider 密钥。
- 快照采用临时文件 + 不可变终态发布；manifest 不是提交点，具体恢复协议见 [本地数据契约](../../../04-技术架构/本地项目与资产契约.md)。
- 首批不提供永久删除项目目录接口；移除最近入口不删除磁盘数据。

### 状态与生命周期

`closed -> opening -> open/dirty -> saving -> open/clean -> closing -> closed`；保存失败不能进入 clean/closed，除非用户明确放弃并确认风险。

## 验收标准

#### AC01 未登录创建并恢复

Given 用户未登录且选择一个可写目录。

When 用户新建项目、保存并重启应用后重新打开。

Then 项目可打开，项目 ID 和最近项目入口稳定，过程不要求网络或账号。

#### AC02 写入失败不丢最后有效版本

Given 项目已有有效保存版本。

When 下一次保存遇到写入失败。

Then UI 显示失败，最后有效版本仍可恢复，项目不得标记为已保存。

#### AC03 越界路径拒绝

Given Renderer 提交未经授权或路径穿越后的项目路径。

When Main 处理打开/写入请求。

Then 请求被拒绝，授权目录外文件未被读取或修改。

#### AC04 并发修订冲突

Given 同一项目的两个写入方基于相同 revision 修改。

When 第二个写入提交。

Then 检测 revision 冲突，不静默覆盖第一个写入；单写窗口内的后台任务和自动保存也必须遵守此规则。

#### AC05 重复打开定位已有窗口

Given 当前实例已在一个可写窗口打开项目。

When 用户通过最近项目、系统打开或等价目录别名再次打开该项目。

Then 激活已有窗口，不创建第二个可写窗口；其他目录中的项目仍可独立打开。

#### AC06 双实例竞争不能同时获得写权限

Given 两个应用实例尝试打开同一规范化项目目录。

When 两个打开请求竞争项目所有权。

Then 只有一个实例取得写权限，另一个返回 PROJECT_IN_USE，且不修改项目正文。

#### AC07 异常退出后安全恢复所有权

Given 项目原持有实例崩溃，或仍运行但暂时没有响应。

When 新实例尝试打开该项目。

Then 原持有者已退出时可安全恢复项目；原持有者仍活跃时不因超时抢占；旧 owner 的迟到写入被拒绝。
