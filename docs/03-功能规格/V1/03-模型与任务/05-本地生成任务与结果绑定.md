## 目标

创作者可从画布节点提交本地自定义模型任务，跟踪任务生命周期，并在成功后将输出作为资产保存且绑定回来源节点。

## 功能边界

包含：本地 Provider 任务提交、后台执行、状态/进度、取消、失败信息、可恢复记录、输出资产和节点关联。

不包含：官方模型、积分、跨设备任务恢复、所有专有 Provider 和自动 Agent 编排。

## 需求说明

### 用户故事

作为创作者，我希望生成任务在后台运行并可在重启后查看结果，以便长时间生成不会阻塞创作并能继续处理输出。

### 业务规则

1. 每个任务记录 projectId、nodeId（可选）、providerId、pluginId/pluginVersion/sourceHash、modelId、能力、输入摘要/引用、状态和输出资产 ID；文本模型结果以受限文本历史保存，不伪造媒体资产。
2. 长任务不得运行在 Renderer 或阻塞 Main；使用受限 Worker/utility process。
3. 外部请求含敏感素材时，在任务提交前展示目标 Provider 与出站内容类别。
4. `queued -> submitting -> running -> downloading -> succeeded`；失败/取消不可伪装为成功。
5. 用户退出应用时可选择等待、请求取消或退出稍后恢复。重启后有 providerTaskId 且插件支持 query 的任务恢复轮询；无法确定是否已受理或没有可靠查询能力的任务进入 `outcome_unknown`，不得自动重发（D007）。
6. 供应商生成结果先写入临时资产，完整校验后才绑定画布节点。

### 主流程

1. 用户从节点选择能力、Provider、模型和参数。
2. Main 读取 Provider 配置和密钥引用并验证任务能力。
3. 用户确认出站内容后提交任务，任务 journal 先写 queued/submitting。
4. Worker 调用 Provider，持续归并状态和进度。
5. 输出下载至项目暂存区，校验后登记 AssetRecord。
6. 将输出 assetId 绑定来源节点并记录 succeeded。

### 异常与边界

- 网络超时发生在请求发送前可安全重试；请求可能已被受理时标记 outcome_unknown 并提供查询/人工恢复。
- 取消若 Provider 不支持，UI 显示“取消请求中/无法取消”，不能伪造 cancelled。
- 应用退出前展示运行任务数量，提供等待、请求取消或退出并稍后恢复；不承诺应用关闭后后台继续执行。
- 资产下载/校验失败不绑定不完整文件；任务历史保留诊断信息且脱敏。
- Provider/模型能力与节点输入不匹配时，在发送网络请求前拒绝。

### 页面与交互

画布节点显示任务状态；任务中心可查看 Provider/model、提交时间、阶段、取消/重试和错误详情。所有重试由用户触发，未知结果需区别展示。

## 接口契约

IPC 草案：submitGeneration、cancelGeneration、retryGeneration、listJobs、getJob、subscribeJobEvents。契约待确认。

| 字段 | 位置 | 类型 | 必填 | 规则 |
| --- | --- | --- | --- | --- |
| projectId | IPC | string | 是 | 当前打开项目 |
| nodeId | IPC | string | 否 | 必须存在且支持该能力 |
| providerId/pluginId/modelId | IPC | string | 是 | 本地已启用插件和模型，能力匹配 |
| idempotencyKey | IPC | string | 是 | Main 生成或校验唯一键 |
| parameters | IPC | object | 是 | 按能力 schema 验证和限长 |
| assetIds | IPC | string[] | 否 | 所有引用必须属于项目并可读 |

### 错误矩阵

| 错误键 | 场景 | 用户提示 |
| --- | --- | --- |
| JOB_MODEL_UNAVAILABLE | 配置/模型不存在或禁用 | 选择有效模型后重试 |
| JOB_INPUT_INVALID | 参数/能力不匹配 | 检查生成参数和参考素材 |
| JOB_AUTH_FAILED | 用户自有 Provider 鉴权失败 | 检查本地 Provider 凭证 |
| JOB_RATE_LIMITED | Provider 限流 | 等待后重试 |
| JOB_OUTCOME_UNKNOWN | 请求受理状态未知 | 请先查询任务状态，避免重复提交 |
| JOB_OUTPUT_INVALID | 返回内容不能校验 | 未写入资产，可查看脱敏诊断 |

## 数据与事务

| 数据 | 操作 | 字段 |
| --- | --- | --- |
| Local Job Journal | R/W | jobId、idempotencyKey、projectId、nodeId、provider/model、state、timestamps、errorKey |
| Job Input | R | 参数、输入 assetIds、Prompt 引用策略待定 |
| Output Asset | W | assetId、jobId、mediaType、hash、size、storageRef |
| Node Binding | W | nodeId、outputAssetIds、jobId |

外部 Provider 调用不能放在本地文件事务中；结果写入采用可恢复的两阶段落盘/提交。

### 状态与生命周期

`queued -> submitting -> running -> downloading -> succeeded`；任意非终态可到 failed；支持取消时 `running -> cancelling -> cancelled`；受理状态不明时 `submitting/running -> outcome_unknown`。非法转换拒绝并写诊断。

## 验收标准

#### AC01 生成结果绑定回节点

Given 项目中存在能力匹配的节点、Provider 和参考资产。

When 用户提交任务且 Provider 返回有效输出。

Then 任务到达 succeeded，输出写入资产库，来源节点通过 assetId 引用输出。

#### AC02 应用重启恢复任务

Given 一个本地任务正在运行或可查询。

When 应用退出并重新启动。

Then 任务从 journal 恢复为真实/未知状态，不重复发起不可幂等的生成请求。

#### AC03 未知受理结果禁止盲目重试

Given 请求超时但 Provider 可能已经受理。

When Runtime 处理超时。

Then 任务进入 outcome_unknown 或等价状态，未自动重复提交，并提供状态查询/明确用户操作。

#### AC04 取消语义真实

Given Provider 不支持取消或取消请求失败。

When 用户点击取消。

Then UI 不报告任务已取消，显示供应商真实状态并保留后续结果处理能力。

#### AC05 无效输出不污染资产库

Given Provider 返回损坏文件、越界大小或错误媒体类型。

When 下载/校验结束。

Then 临时文件不作为有效资产登记，节点不绑定无效结果，任务失败可诊断。

#### AC06 退出后恢复可查询任务

Given 本地任务已有 providerTaskId 且其插件声明并实现查询能力。

When 用户选择退出并重启应用。

Then 任务从 journal 恢复并通过插件 query 继续查询，不重复提交生成请求。

#### AC07 未知结果不自动重发

Given 任务提交结果不明，或插件不支持可靠查询。

When 应用重启恢复任务。

Then 任务显示为 outcome_unknown，提供人工查询/重试操作，不自动再次调用生成接口。
